# Генератор КП Gelster: спецификация переписывания

Дата: 2026-11-11. Статус: решение принято архитектором, ждёт приёмки Ильи.
Развилки и отвергнутые варианты: `docs/decisions.md`. Правила стека для исполнителей: `docs/context/stack.md`.

## 1. Цель и не-цели

**Цель.** Заменить смесь PHP + jQuery + inline-скриптов (`request.php`, `result.php`, `managers/add_manager.php`,
`currency.php`) на приложение React + TypeScript с тонким сервером на Node.js. Функции те же, что сейчас, плюс три
новые из карточки: предпросмотр КП, сразу разбитый на страницы A4; выгрузка в DOCX; единица измерения «рул.».

**Не-цели первой версии.**
- Новый дизайн. Итоговое КП должно выглядеть как сейчас (`Примеры готового КП/`), форма — близко к нынешней.
- Авторизация, учётные записи, общая база проектов. Проекты, как и сейчас, живут в браузере менеджера.
- Перенос проектов, сохранённых старой версией (там хранится сырой `innerHTML`, структуры нет).
- Парсинг произвольных сайтов: только `gelster.ru` и `ooogelingen.ru`.
- Разрыв абзаца посередине между страницами (единица вёрстки — абзац, строка таблицы).
- Серверная генерация PDF, деплой и выбор хостинга (см. «Открытые вопросы»).

## 2. Что есть сейчас (факты из репозитория)

- `request.php` — форма: менеджер, компания, контактное лицо и пол, ссылка на коллекцию, курс евро (кнопка «ЦБ»),
  валюта основных и дополнительных материалов, две таблицы позиций, комментарий по доставке, список проектов
  (localStorage, в кэше лежит `innerHTML` таблиц).
- `result.php` — сервер скачивает страницу по ссылке (`file_get_contents` с выключенной проверкой TLS), выводит куски
  в скрытый `div`, дальше всё делает JS: заголовок со склонением вида покрытия по словарю, текст, главное фото, выбор
  артикулов в модальном окне, таблица артикулов 4 в ряд, таблица характеристик, таблицы расчётов, комментарии.
  Редактирование — `contenteditable` по клику. PDF — `window.print()` после вставки разрывов по координатам
  (`elementFromPoint`), работает ненадёжно.
- `managers/add_manager.php` — загрузка JPG подписи и правка `managers.htm` без какой-либо защиты.
- Селекторы старого парсера (`h1`, `h2`, `.entry-text`, `#collapseExample`, `.entry-photo`, `.collection-container
  .col-auto`, `.caracter-table`) соответствуют вёрстке **ooogelingen.ru**.
- **gelster.ru свёрстан иначе** (проверено 2026-11-11 на `gelster.ru/marmoleum_cocoa.htm`): характеристики — список
  пар «название – значение», а не таблица; картинки артикулов лежат в `./img/collections/...`; отдельного главного
  фото нет; производителя из пути картинки не вывести. Старый код на gelster.ru, скорее всего, не работает.
- В репозитории лежат `Генератор КП Гельстер.exe`, Bootstrap, jQuery, `simple_html_dom.php`, три копии `result*.php`,
  папки `managers/old*` — в новое приложение не переносятся.

## 3. Пользовательские сценарии

1. **Заполнить форму.** Менеджер выбирает себя в списке, вводит компанию, контактное лицо и пол, вставляет ссылку
   на коллекцию, задаёт курс евро (вручную или кнопкой «ЦБ»), валюты, строки основных и дополнительных материалов
   (наименование, количество, единица: `шт.`, `м²`, `пог.м`, `рул.`, цена в рублях), комментарий по доставке.
   Всё сохраняется автоматически в проект; проектов много, есть поиск, выбор, удаление.
2. **Создать КП.** По кнопке приложение запрашивает страницу коллекции через сервер и открывает предпросмотр.
   Если страница не разобралась целиком, КП всё равно открывается: ненайденные блоки пустые, сверху список
   предупреждений («не найдена таблица характеристик»).
3. **Выбрать артикулы.** При первом открытии показывается окно со всеми артикулами коллекции (картинка, номер,
   флажок; «Выбрать все», «Отменить выбор», «Подтвердить»). Выбранные встают таблицей по 4 в ряд. Окно можно
   открыть снова («Добавить артикулы», «Перевыбрать артикулы»).
4. **Отредактировать.** Любой текст на страницах КП правится на месте: заголовок, обращение, абзацы описания,
   подписи артикулов, ячейки характеристик, комментарии, дата. Строку характеристик и абзац можно удалить.
   Числа в таблицах расчётов на странице КП не правятся — они меняются в форме (иначе разойдутся суммы).
5. **Выгрузить.** «Сохранить в PDF» открывает печать браузера: результат постранично совпадает с предпросмотром.
   «Сохранить в DOCX» скачивает файл Word с тем же содержанием, шапкой и подписью менеджера в колонтитулах.
   Имя файла: `КП_<компания>_от_дд.мм.гг`.
6. **Вернуться.** Правки и выбор артикулов сохраняются в проекте. Кнопка «К форме» на странице КП возвращает
   к форме того же проекта: после правки количества или цены КП открывается с новыми таблицами и прежними
   текстовыми правками. Кнопка «Обновить с сайта» перечитывает страницу коллекции (с предупреждением, что правки
   описания и характеристик будут потеряны).
7. **Управлять менеджерами.** Страница `/managers`: добавить (имя + картинка подписи JPG/PNG), удалить.

## 4. Архитектура

```
Браузер (React SPA)                       Node-сервер (Hono)                Внешние сайты
  /            форма          ── GET /api/collection?url= ──►  fetch + cheerio ──► gelster.ru, ooogelingen.ru
  /kp/:id      предпросмотр   ── GET /api/image?url=      ──►  прокси картинок ──► те же хосты
  /managers    менеджеры      ── GET /api/rates           ──►  XML ЦБ (win-1251) ─► cbr.ru
  IndexedDB: проекты          ── /api/managers (CRUD)     ──►  DATA_DIR/managers.json + файлы подписей
                              ◄─ статика собранного клиента
```

**Почему нужен сервер.** Браузер не может прочитать чужую страницу без CORS-заголовков, а для DOCX нужны ещё и
байты картинок. Статические сайты такие заголовки обычно не отдают; XML ЦБ тоже. Исполнитель первой карточки
проверяет это фактом (`curl -sI -H 'Origin: http://localhost' <url>`) и записывает результат в `decisions.md`.
Даже если заголовки вдруг есть, сервер остаётся: он нужен для менеджеров и не зависит от настроек чужого хостинга.

**Сервер намеренно тонкий:** скачать, разобрать, отдать JSON. Вся логика КП (расчёты, вёрстка, экспорт) — в клиенте.

### 4.1. Стек

| Слой | Выбор | Почему |
|---|---|---|
| Язык | TypeScript (strict) | общие типы клиент/сервер, один пакет |
| Клиент | React 19 + Vite, react-router | названо в карточке; SPA из трёх экранов |
| Сервер | Node.js ≥ 22, Hono (`@hono/node-server`) | несколько маршрутов, встроенный `fetch`, запуск одной командой |
| Разбор HTML | cheerio | разбор на сервере, тесты на сохранённых страницах без браузера |
| Схемы | zod | один источник правды для ответа API и формата проекта в IndexedDB |
| Хранилище | IndexedDB через `idb-keyval` | проекты с картинками не влезут в localStorage |
| Очистка HTML | DOMPurify | текст с сайта и из `contenteditable` → белый список тегов |
| DOCX | `docx` (dolanmiu), в браузере | строит документ из модели; колонтитулы, таблицы, картинки |
| PDF | печать браузера, `@page { size: A4; margin: 0 }` | совпадает с предпросмотром, текст векторный, нет зависимостей |
| Тесты | Vitest, Testing Library, Playwright (один сквозной) | |

Bootstrap и jQuery убираются. Шрифты PT Sans / PT Serif, `header.jpg`, `footer.jpg`, иконка, актуальные подписи
менеджеров переезжают как есть. Стили КП — из `style/style.css` без изменения размеров.

## 5. Данные

```ts
// Ответ GET /api/collection
type Collection = {
  sourceUrl: string; site: 'gelster' | 'ooogelingen'; fetchedAt: string;
  name: string;            // h1: «Marmoleum Cocoa»
  flooringKind: string;    // «Натуральный линолеум с какао»
  manufacturer: string;    // «Forbo» или '' если не определён
  descriptionHtml: string; // очищенный HTML: p, ul, ol, li, b, strong, i, em, u, a, br, sup, sub
  mainImage: string | null;                      // абсолютный URL
  articles: { code: string; title?: string; image: string }[];
  features: { cells: { html: string; colSpan?: number; rowSpan?: number; header?: boolean }[] }[];
  warnings: string[];      // что не найдено
};

type Project = {
  id: string; version: 1; updatedAt: string;
  form: {
    managerId: string; client: string; clientName: string; clientSex: 'm' | 'f';
    link: string; euroRate: number | null;
    mainCurrency: 'rub' | 'rubAndEuro'; extraCurrency: 'rub' | 'rubAndEuro';
    mainItems: Item[]; extraItems: Item[];
    delivery: { mode: 'default' | 'none' | 'custom'; custom: string[] };
  };
  collection: Collection | null;      // снимок с сайта
  kp: {                               // правки поверх снимка; null = ещё не открывали
    date: string; title: string; greeting: string; intro: string;
    collectionHeading: string; descriptionHtml: string;
    selectedArticles: { code: string; image: string; caption: string }[];
    featuresTitle: string; features: Collection['features']; comments: string[];
  } | null;
};
type Item = { id: string; name: string; qty: number | null; unit: 'шт.' | 'м²' | 'пог.м' | 'рул.'; priceRub: number | null };
type Manager = { id: string; name: string; signature: string /* URL картинки */ };
```

Правила:
- Проект идентифицируется `id` (uuid), а не названием компании, как сейчас: переименование компании не плодит копии.
- `kp` создаётся из `form` + `collection` при первом открытии предпросмотра и дальше живёт сам. Таблицы расчётов
  всегда строятся из `form` на лету и в `kp` не хранятся.
- Поле `version` обязательно: при изменении формата пишется миграция, а не «Очистить данные».
- Расчёты: сумма строки = `round2(qty × priceRub)`, цена в евро = `round2(priceRub / euroRate)`, итоги — суммы
  округлённых строк. Формат `1 234,56`. Нумерация дополнительных материалов продолжает нумерацию основных.
  При валюте «рубли и евро» курс обязателен (валидация формы; сейчас там деление на ноль).
  Строки без наименования в КП не попадают; пустое количество или цена считаются нулём и подсвечиваются в форме.
- Удалённый менеджер: если `managerId` проекта не найден в списке, КП рисуется с общим `footer.jpg` и
  предупреждением «выберите менеджера»; экспорт не блокируется.
- Картинки, попавшие в КП (главное фото и выбранные артикулы), при выборе сохраняются байтами в отдельное
  хранилище IndexedDB `images` (ключ — URL). Отрисовка и экспорт берут сначала оттуда, потом через `/api/image`.
  Так сохранённый проект не ломается, если сайт убрал товар или недоступен. В самом `Project` остаются URL.

## 6. Внешние интерфейсы (HTTP API)

| Маршрут | Ответ | Ошибки |
|---|---|---|
| `GET /api/collection?url=` | `Collection` | 400 хост не из списка; 502 сайт недоступен; 422 страница не похожа на коллекцию |
| `GET /api/image?url=` | байты картинки, `Cache-Control: max-age=86400` | 400 / 502; не-картинка → 415 |
| `GET /api/rates` | `{ eur: number, usd: number, date: string }` (кэш в памяти 1 ч) | 502 — клиент просит ввести курс вручную |
| `GET /api/managers` | `Manager[]` | |
| `POST /api/managers` | multipart: `name`, `signature` (JPG/PNG ≤ 5 МБ) → `Manager` | 400 |
| `DELETE /api/managers/:id` | 204 | 404 |
| `GET /api/health` | `{ ok: true }` | |

Тело ошибки везде `{ error: string }` — текст по-русски, пригодный для показа пользователю.

**Загрузка чужих адресов (`fetch-allowed.ts`)** — единственное место, где сервер ходит наружу по адресу от клиента
(курс ЦБ запрашивается по зашитому в код адресу и под это правило не попадает):
только `https` (ссылка `http://` или без схемы молча приводится к `https://`); хост строго из списка `gelster.ru`, `www.gelster.ru`, `ooogelingen.ru`, `www.ooogelingen.ru`
(переменная `ALLOWED_HOSTS`); редиректы — вручную и только на хосты из списка; таймаут 10 с; лимит 5 МБ для HTML
и 10 МБ для картинок; проверка TLS включена (в старом коде была выключена — не переносить; если у сайта битый
сертификат, это вопрос к Илье, а не повод её отключать). Кодировка страницы определяется по заголовку и `<meta>`
(XML ЦБ — windows-1251, декодировать через `TextDecoder`).

**Менеджеры.** Хранятся в `DATA_DIR` (по умолчанию `./data-runtime`, вне git): `managers.json` и файлы подписей
с именами, сгенерированными сервером (`<uuid>.jpg`; имя файла от пользователя не используется). Тип файла
проверяется по сигнатуре. Запись — через временный файл и `rename`. При удалении менеджера удаляется и файл подписи.
Картинка коллекции с хоста вне списка (сторонний CDN) не проксируется: она пропускается с предупреждением в
`warnings`; список хостов расширяется через `ALLOWED_HOSTS`.
Переменные окружения: `PORT` (3000), `HOST` (127.0.0.1), `DATA_DIR`, `ALLOWED_HOSTS`, `ADMIN_TOKEN` (необязательная:
если задана, `POST`/`DELETE /api/managers` требуют заголовок `X-Admin-Token`, страница `/managers` спрашивает токен).

## 7. Парсер

Интерфейс: `parseCollection(html: string, url: string): Collection`, чистая функция. Адаптер выбирается по хосту.
Все URL картинок приводятся к абсолютным относительно адреса страницы. HTML описания и ячеек очищается на сервере
(и повторно в клиенте перед вставкой в DOM).

- **ooogelingen.ru** — перенос логики `result.php`: `h1` → `name`; вид покрытия — `h2` у блока описания (ожидаемое
  значение для `m_cocoa.htm`: «Натуральный линолеум с какао»; старый индекс `h2[1]` не копировать вслепую,
  сверить по фикстурам); `.entry-text` + скрытое продолжение `.collapse` → описание; первая картинка `.entry-photo`
  → главное фото; `.collection-container .col-auto` → артикулы (`img` + `span`); `.caracter-table` без первой
  строки → характеристики; производитель — сегмент пути картинки артикула (`Forbo/Marmoleum/...` → `Forbo`).
- **gelster.ru** — новый адаптер, селекторы исполнитель выводит из сохранённых страниц. Характеристики там списком
  пар → превращаются в строки по две ячейки. Главного фото может не быть (`mainImage: null`, блок фото в КП не
  рисуется). Производитель: из хлебных крошек, иначе `''`. Вид покрытия: первый `h2` без названия коллекции
  (на `marmoleum_cocoa.htm` это «Натуральный линолеум marmoleum cocoa» → «Натуральный линолеум»), иначе
  предпоследний пункт хлебных крошек, иначе `''`.
- Пустые `flooringKind` или `manufacturer` не мешают собрать КП: заголовок строится без них («Коммерческое
  предложение на поставку Marmoleum Cocoa»), слова вне словаря склонений остаются как есть; заголовок правится руками.
- Ненайденное поле не роняет разбор: пустое значение + строка в `warnings`. Ошибка 422 — только если нет ни
  названия, ни артикулов, ни описания.
- Фикстуры: не меньше трёх страниц с каждого сайта, разных типов (линолеум, плитка/ковролин, сопутствующий товар
  вроде клея или плинтуса). Вёрстка сайтов меняется — фикстуры и есть договор о том, что поддерживается.

## 8. Страница КП: модель, разбивка на страницы, редактирование

**Модель.** `buildKpDocument(project, manager)` возвращает плоский список блоков в порядке документа:
`date`, `title`, `greeting`, `intro`, `collectionHeading`, `mainImage`, `paragraph` (каждый абзац и пункт списка
описания — отдельный блок), `articleRow` (ряд из ≤ 4 картинок с подписями — неделимый), `paletteLink`,
`featuresHead`, `featureRow`, `calcNote`, `priceHead` / `priceRow` / `priceFoot` (для двух таблиц), `total`, `comment`.
У блока: стабильный `id`, тип, данные, флаги `keepWithNext` (заголовки таблиц, `calcNote`, `collectionHeading`)
и `repeatOnBreak` (шапка таблицы повторяется на новой странице).

**Разбивка.** Страница — `div` 210 × 297 мм: шапка 52,5 мм (`header.jpg`), подвал с подписью менеджера 17,5 мм,
поля контента как в `style.css` (18 мм слева, 15 мм справа). Алгоритм заполнением: блоки по одному добавляются
в скрытый измерительный контейнер с той же шириной и теми же стилями; когда высота превысила доступную, последний
блок (и предшествующие `keepWithNext`) уходят на новую страницу. Измерение — по фактической вёрстке страницы,
а не по сумме высот блоков: главное фото обтекается текстом (`float`), и высота абзацев от него зависит.
Чистая часть (`paginate(blocks, fits) → Page[]`) принимает функцию «помещается ли этот набор блоков на страницу»
и тестируется без браузера. Измеряется всегда страница-кандидат целиком, отрисованная теми же компонентами, что
и настоящая: строки таблицы — внутри своей `<table>` с шапкой, абзацы — с фото или без него, смотря на какой
они странице. Отдельный блок вне контекста не измеряется никогда.
Ряд строк одной таблицы на одной странице отрисовывается одной `<table>`; на следующей — новая с повторённой шапкой
(повторённая шапка входит в измеряемую страницу-кандидат).
Блок выше страницы целиком (очень длинный абзац) ставится один на страницу; область контента страницы имеет
`overflow: hidden`, лишнее обрезается одинаково на экране и в печати, над страницей показывается предупреждение
«текст не помещается, сократите или разбейте абзац». Число страниц в печати поэтому всегда равно числу в предпросмотре.

**Когда пересчитывать.** После загрузки шрифтов и картинок (`document.fonts.ready`, `img.decode()`), после смены
артикулов, удаления блока и по `blur` редактируемого блока. Во время набора текста пересчёта нет: перенос блока на
другую страницу пересоздаёт DOM-узел и сбрасывает курсор.

**Редактирование.** Блок с текстом — `contenteditable`; по `blur` содержимое очищается DOMPurify (те же теги, что
в `descriptionHtml`), пишется в `project.kp`, сохраняется в IndexedDB. Вставка из буфера — только как простой текст.
Удаление строки характеристик и абзаца — кнопкой «×» при наведении (вместо двойного клика, который прятал ячейку
и ломал таблицу). Кнопки управления и «×» не попадают в печать.

**PDF.** В `@media print` видны только страницы, каждая с `break-after: page`, фон и тени убраны, `@page { size: A4;
margin: 0 }`, `print-color-adjust: exact`; шапка и подпись — элементы `<img>`, а не фон (фон Chrome по умолчанию
не печатает). Высота страницы в печати подбирается так, чтобы не появлялся пустой лист после последней
(проверяется сквозным тестом). Перед `window.print()` в `document.title` ставится имя файла. Поддерживаемый браузер — Chrome/Edge
(Chromium); в Firefox допустимы отличия.

**DOCX.** `buildDocx(kpDocument, assets) → Blob` строит документ из той же модели, не из HTML: A4, шапка и подпись —
картинки в колонтитулах раздела во всю ширину листа, поля текста как в предпросмотре; абзацы PT Serif 11,5 pt
с красной строкой и выравниванием по ширине; таблица артикулов 4 × 4 см; характеристики; таблицы расчётов с цветом
«руб.»/«евро». Встроенный HTML блоков (`b`, `i`, `u`, `a`, `br`, `sup`, `sub`) переводится в `TextRun` небольшим
обходом DOM. Пункты списков — отдельные блоки с признаком «маркированный/нумерованный» и в DOCX становятся
абзацами со списочной нумерацией Word, а не текстом. Картинки берутся из хранилища `images`, иначе через `/api/image`. Разбивку на страницы в DOCX делает Word сам, она может
отличаться от предпросмотра — это ожидаемо (строкам таблиц ставится запрет разрыва, шапкам — повтор). Шрифты
встраиваются в файл, если библиотека это делает корректно в Word и LibreOffice; иначе документ ссылается на
PT Sans / PT Serif по имени с запасным Times New Roman / Arial — исполнитель проверяет и фиксирует в `decisions.md`.

## 9. Риски

| Риск | Что делаем |
|---|---|
| Вёрстка сайтов изменится, парсер сломается молча | `warnings` в ответе и на экране; фикстуры; КП открывается и с неполными данными |
| gelster.ru и ooogelingen.ru свёрстаны по-разному, внутри сайта тоже есть разные шаблоны | два адаптера, ≥ 3 фикстуры на сайт; неподдержанный шаблон даёт предупреждения, а не падение |
| Сервер как открытый прокси (SSRF) | белый список хостов, только https, ручные редиректы, лимиты, по умолчанию слушает `127.0.0.1` |
| Загрузка подписей без авторизации | проверка типа и размера, серверные имена файлов, необязательный `ADMIN_TOKEN`; при публикации в интернет токен обязателен |
| Предпросмотр и PDF расходятся | одна и та же DOM-разметка страниц для экрана и печати; сквозной тест печатает PDF и сверяет число страниц |
| DOCX выглядит иначе, чем PDF (шрифты, переносы) | заявлено как ожидаемое; ручная приёмка в Word по чек-листу; встраивание шрифтов |
| Сайт или ЦБ недоступны | понятная ошибка; курс вводится руками; ранее загруженный снимок коллекции остаётся в проекте |
| Данные только в браузере: очистка профиля = потеря проектов | как и сейчас; в v1 — кнопки «Экспорт/Импорт проекта (JSON)» на форме |
| Старые проекты не переносятся | принято как не-цель; старая версия остаётся в `legacy/` до приёмки |
| Потеря функций при переписывании | чек-лист паритета в разделе 10; `legacy/` удаляется последней карточкой после приёмки |
| Сайт убрал товар или картинку — старый проект с дырами | байты картинок, вошедших в КП, лежат в IndexedDB (`images`); остальные картинки коллекции — только URL |

## 10. Как это проверяется

- `npm run typecheck && npm run lint && npm test` — зелёные на каждой карточке.
- Парсер: тесты на фикстурах обоих сайтов (название, вид покрытия, число артикулов и их коды, число строк
  характеристик, абсолютные URL). Загрузчик: тесты отказа для чужого хоста, `http`, редиректа наружу, превышения размера.
- `shared/calc.ts`: суммы, евро, формат, нумерация; `declension.ts`: примеры из словаря.
- `paginate`: тесты с фиктивной функцией измерения (перенос `keepWithNext`, повтор шапки, блок выше страницы).
- DOCX: тест распаковывает файл и проверяет наличие текстов, числа строк таблиц, картинок, колонтитулов.
- Сквозной тест Playwright (API подменён фикстурой): форма → КП → выбор артикулов → правка текста → перезагрузка
  (правка сохранилась) → `page.pdf()` даёт столько же страниц, сколько в предпросмотре → скачался DOCX.
- Чек-лист паритета для ручной приёмки (сравнение с `Примеры готового КП/`): проекты и поиск; менеджер и его
  подпись; обращение по полу; склонение в заголовке; курс ЦБ; валюты и столбец евро; обе таблицы, итоги, общая
  сумма; три режима комментария; выбор, добавление, перевыбор артикулов; правка текста; удаление строк
  характеристик; сохранение правок; PDF; DOCX открывается в Word без предупреждений.

## 11. Открытые вопросы (не блокируют разработку)

1. **Где это будет работать** (офисный компьютер, сервер в сети, хостинг сайта). Приложение — один процесс Node,
   запускается `npm run build && npm start`; от ответа зависят только обвязка запуска и обязательность `ADMIN_TOKEN`.
2. Нужна ли страница управления менеджерами или достаточно править файл руками (сейчас сделана страница).
3. Убрать ли из репозитория `Генератор КП Гельстер.exe` (в истории git он останется).
