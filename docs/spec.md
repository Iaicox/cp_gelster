# Генератор КП Gelster: спецификация переписывания

Дата: 2026-11-11, редакция 2 (после ответов Ильи на страницу ревью). Редакция 1 описывала сервер на Node/Hono —
она заменена целиком. Развилки и отвергнутые варианты: `docs/decisions.md`. Правила стека: `docs/context/stack.md`.

## 1. Цель и не-цели

**Цель.** Заменить смесь PHP + jQuery + inline-скриптов (`request.php`, `result.php`, `managers/add_manager.php`,
`currency.php`) на статическое приложение React + TypeScript и маленькую серверную часть на PHP без фреймворков.
Функции те же, что сейчас, плюс две новые: предпросмотр КП, сразу разбитый на страницы A4, и выгрузка в DOCX,
пригодный для ручной правки.

**Где работает.** Сначала компьютер или сервер в локальной сети офиса, позже — обычный хостинг сайта (есть PHP,
постоянный процесс Node запустить нельзя). Одна и та же сборка (`dist/`) работает в обоих местах: её достаточно
положить в любой каталог веб-сервера с PHP. Node нужен только там, где приложение собирают.

**Не-цели первой версии.**
- Новый дизайн. Итоговое КП выглядит как сейчас (`Примеры готового КП/`), форма — близко к нынешней.
- Учётные записи менеджеров и общая база проектов. Проекты живут в браузере менеджера (IndexedDB).
- Перенос проектов, сохранённых старой версией.
- Парсинг произвольных сайтов: только `gelster.ru` и `ooogelingen.ru`.
- Разрыв абзаца посередине между страницами (единица вёрстки — абзац, строка таблицы).
- Серверная генерация PDF. Совпадение разбивки на страницы между DOCX и PDF.
- Скидки, выделение НДС, ввод цены в евро, единица «рул.» (кандидаты в отдельные карточки, см. раздел 12).

## 2. Что есть сейчас (факты)

- `legacy/request.php` — форма: менеджер, компания, контактное лицо и пол, ссылка на коллекцию, курс евро (кнопка
  «ЦБ»), валюта основных и дополнительных материалов, две таблицы позиций, комментарий по доставке, список проектов.
- `legacy/result.php` — сервер скачивает страницу (с выключенной проверкой TLS), дальше всё делает JS в браузере:
  заголовок со склонением, текст, главное фото, выбор артикулов, таблицы. PDF — `window.print()`, ненадёжно.
- `legacy/managers/add_manager.php` — загрузка подписи и правка `managers.htm` без какой-либо защиты.
- Селекторы старого парсера соответствуют вёрстке **ooogelingen.ru**. **gelster.ru свёрстан иначе** (характеристики
  списком пар, картинки в `./img/collections/...`, главного фото нет).
- gelster.ru, ooogelingen.ru и cbr.ru **не отдают заголовков CORS** (проверено `curl`, см. `decisions.md`): браузер
  не может сам прочитать ни страницу, ни байты картинок, ни XML ЦБ.
- Слитый каркас: Vite + React 19 + react-router, сервер Hono в `server/`, ассеты в `public/`, начальный список
  менеджеров в `data/managers/`. Что в нём меняется — раздел 11.
- На сервере разработки `srv` PHP не установлен (см. раздел 10 «Без PHP»).

## 3. Пользовательские сценарии

1. **Заполнить форму.** Менеджер выбирает себя в списке, вводит компанию, контактное лицо и пол, вставляет ссылку
   на коллекцию, задаёт курс евро (вручную или кнопкой «ЦБ»), для каждой таблицы — показывать ли столбец в евро,
   строки основных и дополнительных материалов (наименование, количество, единица `шт.` / `м²` / `пог.м`, цена
   в рублях), комментарий по доставке. Всё сохраняется автоматически в проект; проектов много, есть поиск, выбор,
   удаление.
2. **Создать КП.** По кнопке приложение загружает страницу коллекции (через PHP-прокси), разбирает её в браузере
   и открывает предпросмотр. Если страница разобралась не целиком, КП всё равно открывается: ненайденные блоки
   пустые, сверху список предупреждений.
3. **Выбрать артикулы.** При первом открытии — окно со всеми артикулами коллекции (картинка, номер, флажок;
   «Выбрать все», «Отменить выбор», «Подтвердить»). Выбранные встают таблицей по 4 в ряд. Окно открывается снова
   кнопками «Добавить артикулы» и «Перевыбрать артикулы».
4. **Отредактировать.** Любой текст на страницах КП правится на месте: заголовок, обращение, абзацы описания,
   подписи артикулов, ячейки характеристик, комментарии, дата. Строку характеристик и абзац можно удалить.
   Числа в таблицах расчётов на странице КП не правятся — они меняются в форме.
5. **Выгрузить.** «Сохранить в PDF» открывает печать браузера; поля и колонтитулы браузера убраны стилями, менеджер
   в диалоге ничего не настраивает. «Сохранить в DOCX» скачивает файл Word с тем же содержанием: настоящие абзацы,
   списки и таблицы, которые менеджер правит руками. Имя файла: `КП_<компания>_от_дд.мм.гг`.
6. **Вернуться.** Правки и выбор артикулов сохраняются в проекте. «К форме» возвращает к форме того же проекта;
   после правки количества или цены КП открывается с новыми таблицами и прежними текстовыми правками. «Обновить
   с сайта» перечитывает страницу коллекции (с предупреждением, что правки описания и характеристик пропадут).
7. **Перенести проекты.** На форме: «Экспорт проекта», «Экспорт всех проектов», «Импорт из файла». Файл содержит
   и картинки, вошедшие в КП. Так проекты переносятся на другой компьютер, в другой браузер и на новый адрес
   приложения (при переезде с офисного сервера на хостинг адрес меняется, а IndexedDB привязана к адресу).
8. **Управлять менеджерами** (генеральный директор). Страница «Менеджеры» сначала спрашивает пароль. После входа:
   список, добавить (имя + картинка подписи JPG/PNG), удалить. Без пароля изменить список нельзя никогда.

## 4. Архитектура

```
Браузер: статическая сборка React                PHP (каталог api/)               Внешние сайты
  #/           форма        ── api/fetch.php?kind=page&url=  ──► cURL, белый список ──► gelster.ru, ooogelingen.ru
  #/kp/:id     предпросмотр ── api/fetch.php?kind=image&url= ──► то же            ──► те же хосты
  #/managers   менеджеры    ── api/rates.php                 ──► XML ЦБ, кэш 1 ч  ──► cbr.ru
  разбор HTML (DOMParser)   ── api/managers.php (GET/POST)   ──► api/data/managers.json + подписи
  IndexedDB: проекты, картинки
  config.json: где API и нужен ли прокси
```

**PHP намеренно «тупой»:** скачать и отдать байты, хранить список менеджеров. Он не разбирает HTML и XML и ничего
не знает о КП. Вся логика (разбор страниц, расчёты, вёрстка, экспорт) — в TypeScript и покрыта тестами без PHP.

**Настройка клиента — `config.json`** рядом с `index.html`, читается при старте (менять можно на хостинге без
пересборки):

```json
{ "apiBase": "api", "fetchMode": "proxy" }
```

- `fetchMode: "proxy"` (по умолчанию) — страницы и картинки идут через `api/fetch.php`.
- `fetchMode: "direct"` — браузер ходит на сайты сам. Нужен, когда на обоих сайтах появятся заголовки CORS
  (`Access-Control-Allow-Origin` для адреса приложения) — у Ильи есть доступ к сайтам. Прокси тогда не используется.
- `apiBase: null` — режим «совсем без сервера»: `fetchMode` считается `direct`, кнопка «ЦБ» скрыта (курс вводится
  руками, у cbr.ru CORS нет), список менеджеров читается из статического `managers.json` рядом с `index.html`
  (правится руками), страница «Менеджеры» сообщает, что управление недоступно.
- Файла нет или он битый — значения по умолчанию и предупреждение в консоли.

**Адреса.** Маршруты клиента — в хэше (`#/kp/<id>`), все ссылки на ассеты и API относительные (`base: './'`).
Поэтому не нужны правила перезаписи адресов на веб-сервере (Apache, nginx — всё равно), и приложение работает
из любого подкаталога сайта.

### 4.1. Стек

| Слой | Выбор | Почему |
|---|---|---|
| Клиент | TypeScript (strict), React 19, Vite, react-router (hash) | решение Ильи; SPA из трёх экранов |
| Сервер | PHP 8.4 / 8.5, без фреймворков и без Composer, расширение `curl` | работает на обычном хостинге; нечего устанавливать |
| Разбор HTML | `DOMParser` в браузере, модуль `shared/parsers` | PHP остаётся тупым; тесты на фикстурах в Vitest (jsdom) |
| Схемы | zod | один источник правды для `Collection`, проекта в IndexedDB, файла экспорта, ответов API |
| Хранилище | IndexedDB через `idb-keyval` | проекты с картинками не влезут в localStorage |
| Очистка HTML | DOMPurify | текст с сайта и из `contenteditable` → белый список тегов |
| DOCX | `docx` (dolanmiu), в браузере | строит документ из модели: стили, списки, таблицы, колонтитулы |
| PDF | печать браузера, `@page { size: A4; margin: 0 }` | совпадает с предпросмотром, текст векторный |
| Тесты | Vitest + jsdom, Testing Library, Playwright; PHP — скрипт без зависимостей | раздел 10 |

**Версия PHP.** Целевая для хостинга — 8.5 (патч не ниже 8.5.12). На `srv` (Debian 13) из штатного репозитория
ставится 8.4. Код обязан работать на 8.4 и 8.5; возможности, появившиеся в 8.5, не используются. При версии ниже
8.4 API отвечает понятной ошибкой. Версия PHP на будущем хостинге неизвестна — это допущение, проверяется
`api/health.php` при установке.

## 5. Данные

```ts
type Collection = {                 // результат parseCollection()
  sourceUrl: string; site: 'gelster' | 'ooogelingen'; fetchedAt: string;
  name: string;            // h1: «Marmoleum Cocoa»
  flooringKind: string;    // «Натуральный линолеум с какао»
  manufacturer: string;    // «Forbo» или ''
  descriptionHtml: string; // очищенный HTML: p, ul, ol, li, b, strong, i, em, u, a, br, sup, sub
  mainImage: string | null;                      // абсолютный URL
  articles: { code: string; title?: string; image: string }[];
  features: { cells: { html: string; colSpan?: number; rowSpan?: number; header?: boolean }[] }[];
  warnings: string[];
};

type Project = {
  id: string; version: 1; updatedAt: string;
  form: {
    managerId: string; managerName: string /* снимок имени на момент выбора */; client: string; clientName: string; clientSex: 'm' | 'f';
    link: string; euroRate: number | null;
    mainCurrency: 'rub' | 'rubAndEuro'; extraCurrency: 'rub' | 'rubAndEuro';   // показывать ли столбец евро
    mainItems: Item[]; extraItems: Item[];
    delivery: { mode: 'default' | 'none' | 'custom'; custom: string[] };
  };
  collection: Collection | null;      // снимок с сайта
  kp: {                               // правки поверх снимка; null = предпросмотр ещё не открывали
    date: string | null; title: string | null; greeting: string | null; intro: string | null;  // null = авто
    collectionHeading: string | null; descriptionHtml: string;
    selectedArticles: { code: string; image: string; caption: string }[];
    featuresTitle: string; features: Collection['features']; comments: string[];
    mainImageHidden: boolean;         // главное фото убрано со страницы КП (раздел 8.1); нет поля = false
    paletteText: string | null;       // текст перед ссылкой на палитру; null = авто
    paletteHidden: boolean;           // строка «Всю палитру…» убрана; нет поля = false
  } | null;
};
type Item = { id: string; name: string; qty: number | null; unit: 'шт.' | 'м²' | 'пог.м'; priceRub: number | null };
type Manager = { id: string; name: string; signature: string /* URL картинки относительно приложения */ };
type Rates = { eur: number; usd: number; date: string };
type ExportFile = { format: 'gelster-kp'; version: 1; exportedAt: string;
                    projects: Project[]; images: Record<string /* URL */, string /* data: URL */> };
```

Правила:
- Цена вводится **только в рублях**. Столбец «евро» — производное: цена `round2(priceRub / euroRate)`, сумма
  строки `round2(qty × цена в евро)`, итог в евро — сумма округлённых строк (в строке «цена × количество = сумма»
  сходится на глаз). Исполнитель сверяет с `legacy/result.php`; если там считалось иначе — оставить как было
  и записать в `decisions.md`. При режиме «рубли и евро» курс обязателен и строго больше нуля (валидация формы;
  в старом коде там деление на ноль).
- Сумма строки = `round2(qty × priceRub)`, итоги — суммы округлённых строк. Формат `1 234,56`. Нумерация
  дополнительных материалов продолжает нумерацию основных. Строки без наименования в КП не попадают; пустое
  количество или цена считаются нулём и подсвечиваются в форме.
- Проект идентифицируется `id`, а не названием компании. `id` генерируется через `crypto.getRandomValues`:
  `crypto.randomUUID()` недоступен на странице, открытой по `http://` с адреса в локальной сети.
- `kp` создаётся при первом открытии предпросмотра. Таблицы расчётов всегда строятся из `form` на лету и в `kp`
  не хранятся. Поля, которые выводятся из формы (дата, заголовок, обращение, вступление, заголовок коллекции),
  хранятся как `null`, пока менеджер их не правил, и тогда пересчитываются при каждом открытии: сменили клиента
  или пол в форме — обращение изменилось. Правленое руками поле больше не пересчитывается; рядом с ним при наведении
  есть кнопка «вернуть авто».
- Сменили ссылку в форме (`form.link` ≠ `collection.sourceUrl`): при открытии КП страница загружается заново после
  подтверждения «описание, характеристики и выбор артикулов будут сброшены»; отказ оставляет прежний снимок.
- Поле `version` обязательно в проекте и в файле экспорта: при изменении формата пишется миграция.
- Картинки, вошедшие в КП (главное фото и выбранные артикулы), сохраняются байтами в хранилище IndexedDB `images`
  (ключ — URL). Отрисовка и экспорт берут сначала оттуда, потом из сети. В `Project` остаются URL.
- Импорт: файл проверяется схемой; проект с уже существующим `id` заменяется только после подтверждения
  («заменить / импортировать как копию / пропустить»). Битый файл — понятная ошибка, данные не трогаются.
- Подпись выбранного менеджера тоже кладётся в `images`, имя — в `form.managerName`. Если менеджера потом удалили,
  старый проект открывается с сохранённой подписью и предупреждением «менеджер удалён из списка». Если подписи нет
  ни в списке, ни в `images` — общий `footer.jpg` и «выберите менеджера»; экспорт не блокируется.
- Старые проекты (localStorage старой версии) не читаются и не переносятся.

## 6. Серверная часть на PHP

Общее: каждый файл начинается с `declare(strict_types=1)`; точки входа подключают `lib/bootstrap.php`. Ответы-ошибки
везде `{ "error": "текст по-русски для показа пользователю" }` с осмысленным статусом. Заголовков CORS API не
отдаёт: клиент и API всегда на одном адресе. Нужные расширения: только `curl` (плюс входящие в ядро `json`,
`standard`). Маршрутизации нет: один файл — одна точка входа; методы только `GET` и `POST`.

| Адрес | Что делает | Ошибки |
|---|---|---|
| `GET api/fetch.php?kind=page&url=` | байты страницы как есть; `Content-Type` исходный; `X-Final-Url` — адрес после редиректов | 400 адрес не разрешён; 502 сайт недоступен / слишком большой ответ; 415 не HTML |
| `GET api/fetch.php?kind=image&url=` | байты картинки, `Cache-Control: max-age=86400` | 400; 502; 415 не картинка (jpeg, png, gif, webp) |
| `GET api/rates.php` | XML ЦБ как есть (windows-1251), кэш в файле 1 ч | 502 — клиент просит ввести курс руками |
| `GET api/managers.php` | `Manager[]` | |
| `POST api/managers.php` `action=login`, `password` | 204, если пароль верен | 401; 429 блокировка; 503 пароль не задан |
| `POST api/managers.php` `action=add`, `password`, `name`, файл `signature` | `Manager` | 400; 401; 413; 429; 503 |
| `POST api/managers.php` `action=delete`, `password`, `id` | 204 | 401; 404; 429; 503 |
| `GET api/health.php` | `{ ok, phpOk, curl, dataWritable, passwordSet }` — только признаки, без версий и путей | |

**Загрузка чужих адресов (`lib/fetch_allowed.php`)** — единственное место, где PHP ходит по адресу от клиента
(адрес ЦБ зашит в код). Обязательные проверки, каждая покрыта тестом:
- схема только `https`; в адресе нет логина/пароля; порт не указан или 443;
- хост после приведения к нижнему регистру строго из списка: `gelster.ru`, `www.gelster.ru`, `ooogelingen.ru`,
  `www.ooogelingen.ru` (ключ `allowed_hosts` в `config.php`); сравнение точное, не по вхождению подстроки;
- cURL: `CURLOPT_PROTOCOLS` и `CURLOPT_REDIR_PROTOCOLS` = только HTTPS; `CURLOPT_FOLLOWLOCATION` выключен,
  редиректы — вручную, не больше 3, каждый новый адрес проходит те же проверки заново;
- проверка TLS включена (`SSL_VERIFYPEER`, `SSL_VERIFYHOST = 2`); отключать нельзя;
- таймауты: соединение 5 с, весь запрос 15 с; лимит ответа 5 МБ для страницы и 10 МБ для картинки, обрыв при
  превышении во время скачивания (не по `Content-Length`);
- адрес, к которому фактически подключился cURL (`CURLINFO_PRIMARY_IP`), не должен быть частным, локальным или
  служебным (`FILTER_FLAG_NO_PRIV_RANGE | FILTER_FLAG_NO_RES_RANGE`, плюс `169.254.0.0/16` и IPv6-аналоги) —
  иначе ответ отбрасывается. Это защита на случай подмены DNS; белого списка она не заменяет;
- тип ответа: `kind=page` — `text/html`; `kind=image` — тип по сигнатуре байтов, а не по заголовку;
- клиенту не пересылаются заголовки исходного сайта, кроме `Content-Type`; cookies не передаются никуда.
Сетевой слой отделён: функция принимает «транспорт» (в работе — cURL, в тестах — подделка), поэтому редиректы,
лимиты и отказы проверяются тестами без сети.

**Менеджеры.** `api/data/managers.json` и `api/data/signatures/<случайное имя>.jpg|png`. Если `managers.json` нет,
он и подписи копируются из `api/seed/` при первом обращении. Запись — под `flock`, через временный файл и `rename`.
При удалении менеджера удаляется файл подписи.
Проверка загружаемой подписи: `is_uploaded_file`; размер ≤ 5 МБ; `getimagesize()` распознаёт JPEG или PNG
(по содержимому, не по имени и не по заявленному типу); стороны ≤ 6000 px; имя файла генерируется сервером
(`random_bytes`), расширение — по распознанному типу; имя от пользователя не используется вообще. Имя менеджера:
обрезка пробелов, 1–100 символов, без управляющих символов.
Служебные файлы (кэш курса, счётчики входов) не должны читаться через веб на любом сервере: встроенный сервер PHP
и nginx не понимают `.htaccess`. Поэтому они лежат в `api/data/private/` как файлы `*.php`, первая строка которых
`<?php http_response_code(404); exit; ?>`, дальше JSON. В `signatures/` попадают только файлы с серверными именами
и расширением `.jpg` / `.png`, исполняться там нечему; `.htaccess` с запретом скриптов кладётся дополнительно.

**Пароль.** Обязателен всегда. В `api/config.php` хранится только хэш (`password_hash`), проверка —
`password_verify`. Пароль задаётся командой `php api/tools/set-password.php` (спрашивает пароль, пишет `config.php`);
на хостинге без командной строки `config.php` готовится на своём компьютере и загружается вместе со сборкой.
Пока пароль не задан, любые `POST` отвечают 503 «Пароль администратора не задан» — список менеджеров при этом
читается. Пароль передаётся полем `password` в каждом изменяющем запросе; сессий и cookies нет. Клиент держит
пароль только в памяти вкладки; `action=login` нужен лишь затем, чтобы страница проверила пароль при входе.
Защита от перебора: счётчик по адресу клиента (`REMOTE_ADDR`) — после 5 неверных попыток за 15 минут проверки
пароля с этого адреса отклоняются на 15 минут (429); каждая неверная попытка отвечает с задержкой 1 с. Общей
блокировки нет, чтобы посторонний не мог запереть директора. `tools/*.php` при вызове через веб отвечают 404.

**Конфигурация (`api/config.php`, возвращает массив):** `admin_password_hash`, `allowed_hosts`. Каталог данных
в первой версии всегда `api/data/` (подписи отдаёт веб-сервер как обычные файлы); в тестах он переопределяется
переменной окружения `GELSTER_DATA_DIR`. Секретов в репозитории нет: `config.php` и `api/data/` в `.gitignore` и не входят в `dist/`. Обновление версии =
заменить всё, кроме `api/config.php`, `api/data/` и `config.json`.

## 7. Разбор страниц (в браузере)

Интерфейс: `parseCollection(html: string, url: string): Collection` — чистая функция в `shared/parsers`, внутри
`new DOMParser().parseFromString(html, 'text/html')`. Такой документ инертен: скрипты не выполняются, картинки
не загружаются. Узлы из него в документ приложения не переносятся: наружу выходят только строки, прошедшие DOMPurify
с белым списком тегов. Адаптер выбирается по хосту. Все URL картинок приводятся к абсолютным относительно
`X-Final-Url`. Байты страницы декодируются `TextDecoder` по `charset` из `Content-Type`; если его нет — по
`<meta charset>`, найденному в первых 2048 байтах, прочитанных как ASCII; иначе UTF-8.

- **ooogelingen.ru** — перенос логики `result.php`: `h1` → `name`; вид покрытия — `h2` у блока описания (для
  `m_cocoa.htm` ожидается «Натуральный линолеум с какао»; старый индекс `h2[1]` не копировать вслепую, сверить
  по фикстурам); `.entry-text` + скрытое продолжение `.collapse` → описание; первая картинка `.entry-photo` →
  главное фото; `.collection-container .col-auto` → артикулы (`img` + `span`); `.caracter-table` без первой строки →
  характеристики; производитель — сегмент пути картинки артикула (`Forbo/Marmoleum/...` → `Forbo`).
- **gelster.ru** — новый адаптер, селекторы исполнитель выводит из сохранённых страниц. Характеристики списком пар →
  строки по две ячейки. Главное фото — `background-image`
  первого `.big-background` (из `style`); нет блока — `null` и предупреждение. Производитель: из хлебных крошек, иначе `''`.
  Вид покрытия: первый `h2` без названия коллекции, иначе предпоследний пункт хлебных крошек, иначе `''`.
- Пустые `flooringKind` или `manufacturer` не мешают собрать КП: заголовок строится без них, слова вне словаря
  склонений остаются как есть; заголовок правится руками.
- Ненайденное поле не роняет разбор: пустое значение + строка в `warnings`. Ошибка «страница не похожа на
  коллекцию» — только если нет ни названия, ни артикулов, ни описания.
- Картинка с хоста вне белого списка (сторонний CDN) в режиме прокси не загружается: пропускается с предупреждением.
- Фикстуры: не меньше трёх страниц с каждого сайта, разных типов (линолеум, плитка или ковролин, сопутствующий
  товар). Фикстуры — договор о том, какая вёрстка поддерживается.
- **Курс ЦБ:** `parseRates(bytes: ArrayBuffer): Rates` — декодирование windows-1251, разбор XML через `DOMParser`,
  учёт `Nominal` и запятой в числе. Тест на сохранённом XML.

## 8. Страница КП: модель, разбивка на страницы, редактирование, экспорт

**Модель.** `buildKpDocument(project, manager)` возвращает плоский список блоков в порядке документа:
`date`, `title`, `greeting`, `intro`, `collectionHeading`, `mainImage`, `paragraph` (каждый абзац и пункт списка
описания — отдельный блок с признаком «обычный / маркированный / нумерованный»), `articleRow` (ряд из ≤ 4 картинок
с подписями — неделимый), `paletteLink`, `featuresHead`, `featureRow`, `calcNote`, `priceHead` / `priceRow` /
`priceFoot` (для двух таблиц), `total`, `comment`. У блока: стабильный `id`, тип, данные, флаги `keepWithNext`
и `repeatOnBreak` (шапка таблицы повторяется на новой странице).

**Разбивка.** Страница — `div` 210 × 297 мм: шапка 52,5 мм (`header.jpg`), подвал с подписью менеджера 17,5 мм,
поля контента как в `style.css` (18 мм слева, 15 мм справа). Блоки по одному добавляются в скрытый измерительный
контейнер с теми же стилями; когда высота превысила доступную, последний блок (и предшествующие `keepWithNext`)
уходят на новую страницу. Измеряется всегда страница-кандидат целиком, отрисованная теми же компонентами, что
и настоящая (главное фото обтекается текстом, высота абзацев от него зависит). Чистая часть
`paginate(blocks, fits) → Page[]` принимает функцию «помещается ли набор блоков» и тестируется без браузера.
Строки одной таблицы на странице — одна `<table>`; на следующей — новая с повторённой шапкой. Блок выше страницы
целиком ставится один на страницу, лишнее обрезается (`overflow: hidden`) одинаково на экране и в печати, над
страницей предупреждение «текст не помещается». Число страниц в печати всегда равно числу в предпросмотре.

**Когда пересчитывать.** После загрузки шрифтов и картинок, после смены артикулов, удаления блока и по `blur`
редактируемого блока. Во время набора текста пересчёта нет (иначе сбрасывается курсор).

**Редактирование.** Блок с текстом — `contenteditable`; по `blur` содержимое очищается DOMPurify, пишется
в `project.kp`, сохраняется. Вставка из буфера — только как простой текст. Удаление строки характеристик и абзаца —
кнопкой «×» при наведении. Enter внутри абзаца описания делит его: по `blur` абзац с несколькими строками-блоками
становится несколькими блоками `paragraph` (так менеджер разбивает абзац, который не помещается на страницу).
Кнопки управления не попадают в печать.

**PDF.** В `@media print` видны только страницы, каждая с `break-after: page` (кроме последней), фон и тени убраны,
`print-color-adjust: exact`; шапка и подпись — элементы `<img>`, а не фон. `@page { size: A4; margin: 0 }` убирает
поля, а вместе с ними дату, адрес и номера страниц, которые браузер печатает в полях: при нулевых полях Chrome и Edge
их не выводят, флажок «Колонтитулы» снимать не нужно. Отступы текста задаются внутри страницы-`div`.
Перед `window.print()` в `document.title` ставится имя файла.
- **Проверка фактом** (архитектор выполнить не смог — в его сессии нельзя запускать браузер; делает карточка
  «Страница КП»): сквозной тест печатает страницу в PDF в Chromium с включёнными колонтитулами и проверяет, что
  в PDF нет строки с адресом и датой, размер листа A4, число листов равно числу страниц предпросмотра, пустого
  листа в конце нет. Результат записывается в `decisions.md`. Плюс пункт ручной приёмки в настоящем диалоге печати.
- **Известная оговорка** (ответ блокнота): правило действует, пока в диалоге печати «Поля» = «По умолчанию».
  Chrome запоминает последний выбор; если менеджер когда-то выбрал «Обычные» или «Настраиваемые», колонтитулы
  вернутся. Средствами страницы это не исправить: в README и на странице КП (подсказка у кнопки) — одна строка
  «если появились поля: Печать → Поля → По умолчанию». Масштаб в диалоге — 100 %.
- Поддерживаемые браузеры — Chrome и Edge. Firefox и Safari управляют колонтитулами сами; отличия допустимы.

**DOCX — для ручной правки.** `buildDocx(kpDocument, assets) → Blob` строит документ из модели, не из HTML.
Требования редактируемости (каждое проверяется тестом по XML внутри файла):
- текст — обычные абзацы с **именованными стилями** («КП Текст», «КП Заголовок», «КП Комментарий» …), оформление
  задано в стилях, а не на каждом куске текста; никаких надписей (text box), рамок и текста картинкой;
- пункты списков — настоящие списки Word (`numbering`), а не символ «•» в тексте;
- характеристики, артикулы и расчёты — настоящие таблицы; строкам запрещён разрыв (`cantSplit`), шапка
  повторяется (`tableHeader`); числа — текст, который можно исправить;
- встроенное оформление (`b`, `i`, `u`, ссылки, `sup`, `sub`, `br`) переводится в `TextRun` обходом DOM;
- шапка и подпись менеджера — картинки в колонтитулах, привязаны к листу (на всю ширину), текст не сдвигают;
  они повторяются на каждом листе, как в предпросмотре и в нынешних КП (это фирменный бланк, а не подпись в конце);
- главное фото — плавающая картинка с обтеканием, как в предпросмотре; если в Word или LibreOffice она ведёт себя
  плохо при правке — отдельным абзацем по центру (исполнитель проверяет и записывает в `decisions.md`);
- A4, поля текста как в предпросмотре, PT Serif 11,5 pt. Шрифты: попытаться встроить в файл; если библиотека этого
  не умеет или Word ругается — ссылаться по имени с запасными Times New Roman / Arial (записать в `decisions.md`).
Разбивку на страницы делает Word; совпадение с PDF не требуется и не проверяется.

### 8.1. Доработки предпросмотра (карточка a804c951, 13.11.2026)

**Главное фото можно убрать.** У блока `mainImage` при наведении кнопка «×» («Удалить главное фото»), как у абзаца.
Нажатие ставит `kp.mainImageHidden = true`: блок не попадает в модель, значит его нет в предпросмотре, PDF и DOCX,
а картинка не запрашивается. Пока фото убрано, в панели инструментов видна кнопка «Вернуть фото»
(`mainImageHidden = false`). `collection.mainImage` не меняется. «Обновить с сайта» и смена ссылки сбрасывают флаг
вместе с описанием (`withCollection`): содержимое с сайта начинается заново.

**Строка «Всю палитру можно посмотреть по ссылке» правится и удаляется.** Блок `paletteLink` получает поле `text`
(`kp.paletteText ?? 'Всю палитру можно посмотреть по ссылке:'`) и `edited`. Текст перед адресом — `Editable`
в одну строку с «вернуть авто» (то же правило, что у авто-полей: пустой или равный авто-тексту → `null`). Сам адрес
не правится: он берётся из формы и остаётся ссылкой. «×» («Удалить ссылку на палитру») ставит
`kp.paletteHidden = true`; в панели появляется «Вернуть ссылку на палитру». Ряд артикулов перед скрытой строкой
не получает `keepWithNext`. В DOCX — тот же текст; скрытой строки нет. Эти два поля «Обновить с сайта» не трогает
(это правка менеджера, а не содержимое сайта).

**Данные.** Три новых поля `kp` объявляются в схеме с `.default(...)` (`false`, `null`, `false`): записи и файлы
экспорта без них читаются как раньше, `version` остаётся 1, шага миграции нет. `createInitialKp` задаёт их явно.

**Промежуток между комментариями.** Отступ 19 px (`kp-gap`) ставится только перед первым комментарием (после таблицы
или текста); между соседними комментариями — 5 px (`kp-gap-small`), как `.comment-text` в старой версии. В DOCX
так уже сделано (отступ только перед первым комментарием) — не менять.

**Предупреждение о производителе.** Производитель — слово в конце авто-заголовка («Коммерческое предложение на
поставку натурального линолеума **Forbo**»). В форме такого поля нет: он определяется при разборе страницы, и только
на ooogelingen.ru (первая папка пути картинки артикула: `/Forbo/Marmoleum/…`). На gelster.ru его на странице нет,
поэтому там предупреждение было всегда, а на ooogelingen.ru — только у плинтуса и клея. Решение (ждёт ответа
Ильи, см. раздел 13): предупреждение заменяется подсказкой «Производитель не определён: при необходимости допишите
его в заголовке КП (щёлкните по заголовку)» и показывается, только пока заголовок авто (`kp.title === null`).
Текст строится в `buildKpDocument`, а не в парсере: из `collection.warnings` старая строка «Не найден
производитель…» отфильтровывается (она сохранена в снимках уже созданных проектов), `fieldWarnings` её больше
не добавляет.

**Страница «Менеджеры», форма добавления.**
- Вёрстка: поля формы — столбцом с промежутком 12 px, подпись поля над полем ввода, кнопка «Добавить» отделена
  16 px сверху; то же для формы входа (пароль и кнопка не слипаются).
- Подпись можно дать тремя способами: выбрать файл, перетащить файл на область «Перетащите картинку сюда или
  вставьте из буфера (Ctrl+V)», вставить из буфера (`paste` на форме, берётся первый файл из
  `clipboardData.files`). Все три пути идут через одну `pick(file)`: та же проверка типа, тот же предпросмотр.
  Область подсвечивается при `dragover`; `drop` вне области браузер не должен превращать в открытие файла
  (`preventDefault` на форме). Картинка из буфера без имени получает имя `signature.png`.
- Сообщение о неподходящем формате: «Загружаемый файл должен быть в формате JPG или PNG.» — и на клиенте,
  и в ответе сервера (`api/lib/image_check.php`, вместо «Подпись должна быть картинкой JPEG или PNG.»).

**Главное фото gelster.ru: живая проверка.** `tests/smoke-live.sh` дополняется: из HTML живой страницы gelster.ru,
полученного через `fetch.php`, достаётся адрес из `.big-background` (тем же правилом, что в парсере) и запрашивается
как картинка через `fetch.php?kind=image` — ответ `image/*`. Разбор на фикстурах и сквозной тест
`e2e/gelster-photo.spec.ts` уже есть. Как обновить установку и проверить руками — раздел «Обновление» в `README.md`.

| Хостинг запрещает исходящие запросы из PHP | видно по `fetch.php` → 502; запасной путь — `fetchMode: direct` + CORS на сайтах |
| PHP как открытый прокси (SSRF) | раздел 6: белый список, только https, ручные редиректы, лимиты, проверка IP; тесты на каждый отказ |
| Загрузка подписей, подбор пароля | проверка содержимого файла, серверные имена, запрет исполнения в каталоге; хэш пароля, блокировка после 5 попыток |
| В локальной сети пароль идёт по `http` открытым текстом | принято для офиса; на хостинге — только `https`; записано в README |
| Обновление сборки затирает менеджеров или пароль | `config.php` и `api/data/` не входят в `dist/`; правило обновления в README |
| Вёрстка сайтов изменится | `warnings` на экране; фикстуры; КП открывается и с неполными данными; правка парсера не требует PHP |
| Данные только в браузере: очистка профиля или смена адреса = потеря проектов | экспорт/импорт (один и все); напоминание об экспорте в README |
| Поля печати вернутся из-за настроек диалога | раздел 8 «Известная оговорка»; сквозной тест; подсказка |
| DOCX выглядит иначе, чем PDF | заявлено как ожидаемое; важна редактируемость; ручная приёмка в Word |
| На `srv` нет PHP | PHP-тесты пропускаются с громким предупреждением; `REQUIRE_PHP=1` делает пропуск ошибкой |
| Встроенный сервер PHP не рассчитан на нагрузку | для офиса из нескольких человек допустим; в README — вариант с Apache/nginx |
| Потеря функций при переписывании | чек-лист паритета; `legacy/` удаляется последней карточкой после приёмки |

## 10. Как это запускается и проверяется

**Разработка.** `npm run dev` поднимает Vite (5173) и `php -S 127.0.0.1:8081 -t .` (каталог `api/` из корня
репозитория); Vite проксирует `/api` на PHP. Нет PHP — `npm run dev:client`: интерфейс работает, сетевые функции
показывают ошибку.
**Сборка и запуск.** `npm run build` → `dist/` (клиент + `api/`). `npm start` = `php -S 127.0.0.1:8080 -t dist`
(для офиса `HOST=0.0.0.0`). На хостинге — загрузить содержимое `dist/` в каталог сайта, открыть `api/health.php`.

**Проверки** (`tests/run.sh` — единая точка):
- `npm run typecheck && npm run lint && npm test` — на каждой карточке.
- Парсеры: тесты на фикстурах обоих сайтов (название, вид покрытия, число артикулов и коды, число строк
  характеристик, абсолютные URL, отсутствие `script`/обработчиков в выходном HTML). `parseRates` — на сохранённом XML.
- `shared/calc.ts`, `declension.ts`, `paginate` (с фиктивной функцией измерения), хранилище и экспорт/импорт
  (`fake-indexeddb`), клиент API (подменённый `fetch`: режимы `proxy`, `direct`, `apiBase: null`).
- PHP, модульно (`php tests/php/run.php`, без Composer): проверка адреса (чужой хост, `http`, порт, логин в адресе,
  хост-обманка вида `gelster.ru.evil.com`), редирект наружу, превышение размера, частный IP — через поддельный
  транспорт; проверка подписи (не картинка, PHP-файл с расширением .jpg, слишком большая); хранилище менеджеров;
  блокировка после 5 попыток. Плюс `php -l` для всех файлов.
- PHP, эндпоинты (`tests/php-api.test.ts`): Vitest поднимает `php -S` на свободном порту с временным каталогом
  данных и проверяет: `health`; отказы `fetch.php`; `managers.php` — список из seed, вход, добавление с настоящим
  JPEG, отказ без пароля и с неверным, удаление, 503 без заданного пароля. Живую сеть тесты не используют.
- **Без PHP.** Если `php` не найден, оба набора PHP-тестов пропускаются, `tests/run.sh` печатает заметное
  «PHP НЕ НАЙДЕН: тесты PHP ПРОПУЩЕНЫ» и завершается успешно; с `REQUIRE_PHP=1` — ошибкой. Для `srv`:
  `sudo apt install php-cli php-curl` (Debian 13 → PHP 8.4). Всё остальное от PHP не зависит.
- DOCX: тест распаковывает файл и проверяет стили абзацев, списки, таблицы, картинки, колонтитулы.
- Сквозной тест Playwright (сеть подменена фикстурами, PHP не нужен): форма → КП → выбор артикулов → правка текста →
  перезагрузка (правка сохранилась) → PDF (число листов, нет колонтитулов браузера) → скачался DOCX →
  экспорт и импорт проекта.
- Живая проверка (вручную или `tests/smoke-live.sh`, не входит в `run.sh`): настоящие страницы обоих сайтов и курс ЦБ.
- Чек-лист паритета для ручной приёмки Ильи (`docs/acceptance.md`, создаётся предпоследней карточкой).
