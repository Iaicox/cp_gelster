# Архитектурные решения

Формат: дата, решение, почему, что отвергли.

## 2026-11-11. Тонкий сервер на Node.js вместо чисто клиентского приложения
> **Заменено 2026-11-11 (редакция 2):** сервера на Node нет, см. «Статика + маленький PHP вместо сервера на Node».
> Проверка заголовков CORS ниже остаётся в силе.

**Решение.** SPA на React + сервер на Hono: прокси страниц и картинок, курс ЦБ, список менеджеров.
**Почему.** Браузер не читает чужие страницы и байты картинок без CORS-заголовков; DOCX требует байты картинок;
XML ЦБ тоже без CORS; добавление менеджера требует записи файла. Карточка прямо допускает Node при невозможности
обойтись клиентом.
**Отвергли.** (а) Только статика на том же домене, что и сайт: закрывает один сайт из двух, требует доступа к
хостингу сайта, не решает менеджеров. (б) Публичные CORS-прокси: чужой сервис в середине, нестабильно.
(в) Оставить PHP: противоречит карточке.
**Проверить фактом.** Архитектор не смог выполнить `curl` (в сессии разрешён только git). Первая карточка
проверяет заголовки обоих сайтов и дописывает результат сюда. На решение это не влияет (см. spec, раздел 4).
**Проверено 2026-11-11** (`curl -sI -H 'Origin: http://localhost' <url>`, плюс GET и preflight `OPTIONS` для двух адресов):
ни один ответ не содержит `Access-Control-Allow-Origin` и других `Access-Control-*` заголовков, все отвечают 200.
- `https://gelster.ru/marmoleum_cocoa.htm` — 200, `text/html;charset=utf-8`, CORS нет (preflight `OPTIONS` — 200 без CORS).
- `https://gelster.ru/img/collections/marmoleum/m_cocoa/3584.jpg` — 200, `image/jpeg`, nginx, CORS нет.
- `https://ooogelingen.ru/m_cocoa.htm` — 200, `text/html;charset=utf-8`, CORS нет.
- `https://ooogelingen.ru/Forbo/Marmoleum/Cocoa/3580.jpg` — 200, `image/jpeg`, nginx, CORS нет.
- `https://www.cbr.ru/scripts/XML_daily.asp` — 200, `application/xml; charset=windows-1251`, CORS нет (и в HEAD, и в GET).
Вывод: браузер не может прочитать ни страницы, ни байты картинок, ни XML ЦБ напрямую — сервер-прокси нужен.

## 2026-11-11. Каркас: зависимости и запуск без сборки сервера
> **Частично заменено 2026-11-11 (редакция 2):** `server/`, `hono`, `@hono/node-server`, запуск `node server/index.ts`
> и раздача `dist/` сервером убираются. Клиентская часть (Vite, React, TypeScript 6.0, Vitest, ESLint) остаётся.

**Решение.** Сервер на TypeScript запускается самим Node (`node server/index.ts`, встроенное удаление типов,
Node ≥ 22.18), без отдельной компиляции и без `tsx`. Поэтому в `tsconfig` включены `erasableSyntaxOnly` и
`allowImportingTsExtensions`, импорты пишутся с расширением `.ts`. Клиент собирается Vite в `dist/`; сервер раздаёт
`dist/`, если там есть `index.html`, остальные не-API пути отдают `index.html` (маршруты SPA).
В разработке Vite (5173) проксирует `/api` на сервер (3000).
**Зависимости каркаса.**
- `react`, `react-dom`, `react-router` — клиент (спека, 4.1).
- `hono`, `@hono/node-server` — сервер (спека, 4.1).
- `vite`, `@vitejs/plugin-react` — сборка клиента и dev-сервер.
- `typescript` 6.0 — проверка типов; 7.x не взят, потому что `typescript-eslint` пока поддерживает только < 6.1.
- `vitest` — тесты (спека, 4.1).
- `eslint`, `@eslint/js`, `typescript-eslint`, `eslint-plugin-react-hooks`, `globals` — `npm run lint`.
- `concurrently` — `npm run dev` поднимает сервер и Vite одной командой и гасит оба по Ctrl+C на любой ОС.
- `@types/node`, `@types/react`, `@types/react-dom` — типы.
**Отвергли.** `tsx` в production (лишняя зависимость при наличии встроенного удаления типов); сборку сервера через
`tsc` в отдельный каталог (лишний шаг и второй набор путей); фоновый запуск через `&` в `npm run dev`
(не работает в Windows и оставляет процессы).

## 2026-11-11. Страницу разбирает сервер и отдаёт JSON
> **Заменено 2026-11-11 (редакция 2):** разбор переехал в браузер, см. «Разбор страниц в браузере через DOMParser».

**Решение.** `parseCollection(html, url)` на cheerio в `server/parsers`, отдельный адаптер на каждый сайт.
**Почему.** Тесты на сохранённых страницах без браузера; клиент не знает о вёрстке сайтов; URL приводятся
к абсолютным в одном месте. Вёрстка gelster.ru и ooogelingen.ru разная (проверено на странице Marmoleum Cocoa
обоих сайтов), общий набор селекторов невозможен.
**Отвергли.** Отдавать сырой HTML и разбирать `DOMParser` в клиенте (как фактически делает `result.php`):
логика размазана, чужой HTML попадает в DOM приложения.

## 2026-11-11. PDF через печать браузера, без серверного рендера
**Решение.** Предпросмотр — настоящие страницы A4 в DOM; печать выводит их же (`@page margin: 0`).
**Почему.** Совпадение предпросмотра и результата по построению, векторный текст, ноль зависимостей; так привыкли
работать сейчас. Сервер рассчитан на слабую машину, headless-браузер на нём не нужен.
**Отвергли.** Puppeteer/Playwright на сервере (сотни МБ, память, второй движок вёрстки для поддержки);
html2canvas + jsPDF (растр, текст не выделяется); Paged.js (рассчитан на статичный документ, а у нас
редактируемый, плюс собственная разбивка таблиц с повтором шапки проще, чем подстройка под полифил).

## 2026-11-11. Собственная разбивка на страницы по блокам
**Решение.** Документ — плоский список блоков; страницы набираются заполнением с измерением в скрытом контейнере;
пересчёт по `blur`, а не на каждое нажатие.
**Почему.** Старый способ (`elementFromPoint` + масштабирование body) ненадёжен. Блочная модель одновременно
нужна для DOCX и для сохранения правок. Пересчёт по `blur` не сбрасывает курсор.
**Отвергли.** Разрыв внутри абзаца (сложно, для КП на 2–3 страницы не окупается); CSS `break-inside` без
собственных страниц (нет постраничного предпросмотра с шапкой и подвалом на каждой странице).

## 2026-11-11. DOCX строится из модели библиотекой `docx` в браузере
**Решение.** `buildDocx(kpDocument, assets)`; шапка и подпись — в колонтитулах; разбивку на страницы делает Word.
**Почему.** Конвертеры HTML → DOCX дают плохой результат на таблицах, обтекании и колонтитулах; модель блоков
уже есть. Генерация в браузере не нагружает сервер.
**Отвергли.** `html-docx-js` / `html-to-docx` (altChunk или грубая конвертация); генерацию на сервере
(нет причин); более новые пакеты вроде `@office-open/docx` (молодые, версии 0.x) — вернуться к ним, если
`docx` не справится со встраиванием шрифтов; шаблон `.docx` с подстановкой (docxtemplater, carbone) — предложено
Gemini: число артикулов, строк и абзацев переменное, в ячейках картинки и форматированный текст; вставка картинок
в docxtemplater — платный модуль, carbone требует LibreOffice на сервере.

## 2026-11-11. Картинки, вошедшие в КП, сохраняются байтами в IndexedDB
**Решение.** Хранилище `images` (ключ — URL) для главного фото и выбранных артикулов; в `Project` остаются URL.
**Почему.** Иначе сохранённый проект зависит от того, что сайт не убрал товар и доступен (замечание Gemini).
**Отвергли.** Хранить все картинки коллекции (десятки МБ на проект); хранить только URL.

## 2026-11-11. Цена вводится только в рублях, скидок и выделения НДС нет
> **Подтверждено Ильёй 2026-11-11**, дополнено записью «Единицы и цены» ниже.

**Решение.** Оставить как в текущей версии.
**Почему.** Задача — перенос существующих функций; это новые функции, их решает Илья отдельной карточкой.

## 2026-11-11. Проекты в IndexedDB как структурированные данные с версией
**Решение.** `Project { id, version, form, collection, kp }`, ключ — uuid; экспорт/импорт проекта в JSON.
**Почему.** Сейчас в хранилище лежит `innerHTML` таблиц и блоков: его нельзя ни проверить, ни мигрировать,
ни превратить в DOCX. Ключ по названию компании плодит дубликаты при переименовании.
**Отвергли.** Перенос старых сохранённых проектов (нет структуры; другой origin); серверную базу проектов
(нужна авторизация, в карточке не просили).

## 2026-11-11. Менеджеры: файл + каталог подписей на сервере, страница управления сохранена
> **Частично заменено 2026-11-11 (редакция 2):** хранение — в PHP (`api/data/`), пароль обязателен всегда,
> см. «Менеджеры: хранилище в PHP и обязательный пароль». Страница управления остаётся.

**Решение.** `DATA_DIR/managers.json` + файлы с серверными именами; `/api/managers`; необязательный `ADMIN_TOKEN`.
**Почему.** Карточка требует сохранить существующие функции; старая реализация принимает любой файл с любым
именем и переписывает `managers.htm` присланным текстом — это переносить нельзя.
**Отвергли.** Список в коде (каждый новый менеджер = правка репозитория и пересборка); хранение в браузере
(список не общий для всех пользователей).

## 2026-11-11. Проверка TLS при загрузке страниц включена
**Решение.** Не переносить `verify_peer => false` из `result.php`.
**Почему.** Отключённая проверка позволяет подменить страницу. Если сертификат сайта неисправен — чинить сайт.

# Редакция 2: решения после ответов Ильи на страницу ревью

## 2026-11-11. Статика + маленький PHP вместо сервера на Node
**Решение (Илья).** Клиент — статическая сборка React. Серверная часть — PHP без фреймворков в `api/`: прокси
страниц и картинок, курс ЦБ, менеджеры. Сервер на Hono из каркаса удаляется.
**Почему.** Приложение сначала работает в локальной сети офиса, потом, скорее всего, переезжает на обычный хостинг
сайта: там есть PHP, а постоянный процесс Node запустить нельзя. Одна сборка должна работать в обоих местах без
переписывания. Прокси всё равно нужен: gelster.ru, ooogelingen.ru и cbr.ru не отдают заголовков CORS (проверено,
см. первую запись).
**Отвергли.** (а) Node/Hono — не запускается на хостинге; держать две серверные части (Node для офиса, PHP для
хостинга) — двойная поддержка и двойная поверхность атаки. (б) «Совсем без сервера» прямо сейчас — нужны правки
настроек обоих сайтов, не решает курс ЦБ и менеджеров с паролем; оставлено как режим на будущее (следующая запись).
(в) PHP-фреймворк (Slim, Laravel) или Composer — четыре файла-точки входа этого не оправдывают, а на хостинге
появляется шаг установки. (г) Публичные CORS-прокси — чужой сервис в середине. (д) Разбор страниц в PHP —
см. запись про DOMParser.

## 2026-11-11. Адрес API и прокси — настройка `config.json`, прокси можно отключить
**Решение.** Рядом с `index.html` лежит `config.json`: `apiBase` (`"api"` или `null`) и `fetchMode` (`"proxy"` или
`"direct"`). Читается при запуске, меняется без пересборки. `apiBase: null` — режим без сервера: прямые запросы,
курс руками, менеджеры из статического файла.
**Почему.** Илья может добавить заголовки CORS на сайты и разместить приложение на одном из них; переход не должен
требовать правки кода.
**Отвергли.** Переменные сборки Vite (`VITE_*`) — нужна пересборка под каждое место установки.

## 2026-11-11. Маршруты в хэше и относительные адреса
**Решение.** `createHashRouter` (`#/kp/<id>`), `base: './'` в Vite, все адреса ассетов и API относительные.
**Почему.** Нет серверной перезаписи адресов: работает под Apache, nginx и встроенным сервером PHP без настройки,
из любого подкаталога сайта. При маршрутах в пути прямой заход на `/kp/<id>` давал бы 404 без правил веб-сервера,
а какой сервер будет на хостинге — неизвестно.
**Отвергли.** `.htaccess` с перезаписью (только Apache); скрипт-маршрутизатор `index.php` (PHP отдаёт статику —
лишнее и медленнее).

## 2026-11-11. Разбор страниц в браузере через DOMParser
**Решение (Илья).** PHP отдаёт байты страницы как есть; `parseCollection(html, url)` живёт в `shared/parsers`
и работает на `DOMParser`; тесты — Vitest + jsdom на сохранённых страницах. Курс ЦБ тоже разбирается в браузере
(`parseRates`), PHP отдаёт XML как есть.
**Почему.** PHP остаётся минимальным и не требует расширений `dom`/`xml`/`mbstring`; логика разбора одна, на
TypeScript, тестируется без PHP (на `srv` его пока нет); в режиме без прокси тот же код работает без изменений.
**Чем закрыт прежний довод «чужой HTML попадает в DOM приложения»:** документ `DOMParser` инертен (скрипты не
выполняются, ресурсы не грузятся), его узлы в документ приложения не переносятся, наружу выходят строки после DOMPurify.
**Отвергли.** cheerio в браузере (лишние ~300 КБ при наличии встроенного разборщика); разбор в PHP (`DOMDocument`
плохо переносит HTML5, вторая реализация логики, зависимость тестов от PHP).

## 2026-11-11. Версия PHP: 8.5 на хостинге, код совместим с 8.4 и 8.5
**Решение (Илья).** Брать поддерживаемую ветку с последними исправлениями безопасности. Целевая версия хостинга —
8.5, патч не ниже 8.5.12. Код обязан работать на 8.4 и 8.5; возможности только 8.5 не используются. При версии
ниже 8.4 API отвечает ошибкой.
**Факты с php.net на 2026-11-11.** Активная поддержка: 8.4 (до 31.12.2026, исправления безопасности до 31.12.2028)
и 8.5 (до 31.12.2027, безопасность до 31.12.2029). Последний выпуск с исправлениями безопасности — 8.5.12 от
21.10.2026. 8.2 и 8.3 получают только исправления безопасности, 8.6 — в статусе RC. На `srv` (Debian 13) из
штатного репозитория ставится 8.4 с исправлениями безопасности от Debian.
**Допущение.** Версия PHP на будущем хостинге неизвестна; проверяется `api/health.php` при установке. Требования
к хостингу записываются в README (первая карточка).
**Отвергли.** Понизить планку до 8.1–8.3 (предложение Gemini: на массовых хостингах 8.4+ может не быть) — ветки
без активной поддержки; если на хостинге окажется только такая, это решение Ильи, код при этом почти наверняка
заработает после правки одной константы.

## 2026-11-11. PHP без Composer; тесты — свой скрипт и Vitest поверх `php -S`
**Решение.** Модульные тесты — `tests/php/run.php` (простые проверки, без зависимостей). Тесты эндпоинтов —
`tests/php-api.test.ts`: Vitest поднимает встроенный сервер PHP и ходит по HTTP. Сетевой слой прокси принимает
транспорт, в тестах он подменяется. Нет `php` — тесты PHP пропускаются с заметным предупреждением
(`REQUIRE_PHP=1` превращает пропуск в ошибку).
**Почему.** PHP-кода мало (≈ 5 файлов); PHPUnit тянет Composer и десятки пакетов; один прогон `tests/run.sh`
должен работать и там, где PHP ещё не установлен.
**Отвергли.** PHPUnit / Pest; тесты только через живую сеть; «тестовый режим» в боевом коде, разрешающий
`http://127.0.0.1` в белом списке (лазейка в защите от SSRF).
**Для `srv`:** `sudo apt install php-cli php-curl`.

## 2026-11-11. Защита прокси от SSRF в PHP
**Решение.** Только `https`, точное совпадение хоста с белым списком, без логина и нестандартного порта;
`CURLOPT_PROTOCOLS`/`REDIR_PROTOCOLS` = HTTPS; `FOLLOWLOCATION` выключен, редиректы вручную (≤ 3) с повторной
проверкой; проверка TLS включена; таймауты и лимит размера с обрывом при скачивании; проверка фактического адреса
подключения (`CURLINFO_PRIMARY_IP`) на частные и служебные диапазоны.
**Почему.** Рекомендации из блокнота проекта (белого списка и https недостаточно: редиректы, подмена DNS,
протоколы). На хостинге прокси доступен из интернета.
**Отвергли.** Предварительное разрешение имени и `CURLOPT_RESOLVE` (сложнее; при белом списке из своих сайтов
проверка адреса после подключения даёт ту же гарантию для GET-запросов без побочных эффектов);
`file_get_contents` с контекстом (нет контроля редиректов и размера).

## 2026-11-11. Менеджеры: хранилище в PHP и обязательный пароль
**Решение (Илья: страница остаётся, пользуется генеральный директор, пароль обязателен всегда).**
`api/data/managers.json` + подписи с серверными именами. В `api/config.php` — хэш пароля (`password_hash`);
задаётся `php api/tools/set-password.php`. Пока пароль не задан, изменения отклоняются (503). Пароль передаётся
в каждом изменяющем запросе, сессий нет. Перебор: счётчик по адресу клиента, 5 попыток за 15 минут, задержка 1 с.
Служебные файлы — `*.php` с `exit` в первой строке.
**Почему.** Сессии PHP требуют настройки каталога сессий и cookies, на общем хостинге это ещё одна точка отказа;
для одного пользователя и редких действий достаточно пароля в запросе. `.htaccess` не работает во встроенном
сервере PHP и в nginx, поэтому закрывать служебные файлы им нельзя (замечание Gemini).
**Отвергли.** Необязательный токен (прежнее решение); пароль открытым текстом в конфигурации; «задать пароль при
первом заходе на страницу» (на хостинге первым зайдёт кто угодно); общую блокировку после неверных попыток

## 2026-11-12. PHP-часть: прокси, курс ЦБ, менеджеры (карточка 811879ef)
**Решение.**
- `lib/fetch_allowed.php`: адрес от клиента пересобирается из разобранных частей (`https://<хост><путь>?<запрос>`),
  и cURL получает только эту строку — расхождение разборщиков URL исключено. Не-ASCII в пути кодируется
  (`rawurlencode` по байтам), пробелы, управляющие символы и `\` — отказ. Помимо проверки `CURLINFO_PRIMARY_IP`
  после ответа, `CURLOPT_PREREQFUNCTION` (есть с PHP 8.4) обрывает соединение с непубличным адресом до отправки
  запроса. Запрещённые диапазоны: флаги `filter_var` плюс явный список (в т. ч. `100.64.0.0/10` — адреса Tailscale,
  `::ffff:0:0/96`, NAT64, 6to4, Teredo). `CURLOPT_PROXY = ''` — прокси из окружения не используется.
- Ответ на `kind=page` получает `Content-Security-Policy: sandbox`: открытая напрямую страница сайта не исполняет
  скрипты в источнике приложения. Картинка отдаётся с типом по сигнатуре, а не по заголовку сайта.
- Редирект на неразрешённый адрес и четвёртый редирект — 502 (исходный адрес был разрешён, отказал сайт).
- `rates.php` ходит к ЦБ через тот же `fetch_allowed` (хосты `www.cbr.ru`, `cbr.ru`), ответ без `<ValCurs` — 502.
  Устаревший кэш при недоступности ЦБ не отдаётся (по спеке: 502, курс руками).
- Служебные файлы: `data/private/<имя>.php` (кэш курса, счётчики входов) и блокировки `<имя>-lock.php` — все
  с первой строкой-заглушкой 404. Блокировка отдельным файлом: `rename` заменяет inode файла данных.
- Счётчик входов: пустой пароль считается неверной попыткой; проверка пароля идёт под блокировкой, чтобы
  параллельные запросы не обходили лимит. Задержка 1 с — в `managers.php`, не в библиотеке (тесты без ожидания).
- `GELSTER_CONFIG` — путь к `config.php` для тестов (как `GELSTER_DATA_DIR`), иначе тесты эндпоинтов не могли бы
  задать тестовый пароль, не трогая `api/config.php` разработчика.
- id нового менеджера — 16 hex-символов из `random_bytes`; имя файла подписи — 32 hex-символа + расширение
  по `getimagesize`. Ответ на `add` — 200 с `Manager`.
**Отвергли.** Проверку размера по `Content-Length`; `GLOB_BRACE` (нет на части платформ); `curl_close`
(в 8.5 объявлен устаревшим).

## 2026-11-12. Выбор артикулов и правка текста на странице КП (карточка b21ac916)
**Решение.**

- «Добавить артикулы»: уже выбранные отмечены и заблокированы, новые добавляются в конец. «Перевыбрать артикулы»:

  обращение, вступление, заголовок коллекции и комментарии сохраняются.

  страница рендерит ту же разметку без него. Кнопки «×» и «вернуть авто» абсолютно позиционированы (высоту страницы

  По blur: абзацы и ячейки — `sanitizeHtml` (DOMPurify, белый список спеки); однострочные поля (дата, заголовки,
  обращение, вступление, подписи, комментарии) — только текст (`textContent`), разметка в них не хранится.
  Вставка — только `text/plain`, перетаскивание запрещено. Enter в однострочном поле завершает правку,

единственным местом, где задаётся доставка, и показывает правку. Опустошённая строка удаляется.
**Отвергли.** Плавающую панель управления над страницей (сложнее, а абсолютные кнопки внутри блока не влияют
на разбивку); `visibility: hidden` для кнопок (недоступны с клавиатуры и для чтения экрана).

## 2026-11-12. DOCX: шрифты встраиваются в файл
**Решение.** `docx` 9.15.3 встраивает TTF (`Document.fonts`: обычное, полужирное, курсив, полужирный курсив;
файлы `word/fonts/font*.odttf`, обфускация по ECMA-376, в `settings.xml` — `w:embedTrueTypeFonts`). В файл кладутся
все 8 начертаний PT Serif и PT Sans из `public/fonts` (лицензия ParaType Free Font разрешает встраивание).
Шрифты не загрузились — файл собирается без них, стили ссылаются на PT Serif / PT Sans по имени.
**Проверено.** Модульный тест распаковывает файл, находит в `fontTable.xml` все четыре `embed*` для обоих
семейств, снимает обфускацию с `odttf` ключом из `fontKey` и сравнивает с исходным TTF побайтно — совпадает.
Все XML-части файла из сквозного теста корректны (разобраны XML-парсером).
**Не проверено.** Открытие в Word и LibreOffice: на `srv` нет ни того, ни другого (`soffice` не установлен).
Это пункт ручной приёмки (`docs/acceptance.md`, раздел DOCX). Если Word предупредит о файле или не покажет
PT Serif — убрать опцию `fonts` в `buildDocxDocument` (одна строка): останется ссылка по имени, Word подставит
замену (Times New Roman / Arial у пользователей без PT-шрифтов).
**Цена.** Шрифты — около 3,1 МБ без сжатия, файл КП с ними около 2 МБ. Для письма допустимо.
**Отвергли.** Встраивать только PT Serif (таблицы, дата и заголовок набраны PT Sans — без него они поменяли бы вид);
запасную ссылку `w:altName` (библиотека не пишет её для встроенных шрифтов, а Word без неё подставляет шрифт сам).

## 2026-11-12. DOCX: главное фото — плавающая картинка с обтеканием «вокруг рамки»
**Решение.** Фото привязано к первому абзацу описания (`wp:anchor`, по горизонтали от колонки, по вертикали
от абзаца, `wrapSquare`, текст справа, отступ 15 px справа и снизу), ширина — треть колонки минус отступ, как

себя плохо — заменить в `body()` плавающее фото (`mainPhoto`) на встроенное в отдельном абзаце: это уже готовая
ветка «нет абзацев описания».
