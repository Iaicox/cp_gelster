# Генератор КП Gelster: доработки после первой версии

Дата: 2026-11-14 (карточка 7d44eec9). Дополняет `docs/spec.md`: всё, что здесь не названо, остаётся как в спеке.
Решения Ильи и отвергнутое — `docs/decisions.md` (записи от 2026-11-14). Правила оформления интерфейса —
`docs/context/design.md`. Страница, по которой решали, — `docs/review/index.html`.

## 1. Цель и не-цели

**Цель.** Менеджер тратит меньше времени на одно КП, не теряет работу от случайного действия и от чистки браузера,
а в КП появляются скидка, НДС, условия предложения и несколько коллекций.

**Этап 1 (карточки этой задачи):** новое оформление интерфейса без изменения листа КП (раздел 2); удобства формы
и списка проектов, резервная копия (3); строки материалов, окно артикулов, правка менеджера (4); скидка, НДС,
единицы, условия предложения (5); страница КП: отмена, свои блоки, артикулы, дата (6); несколько коллекций (7).
**Этап 2 (отдельная нарезка, раздел 8):** данные сервера вне каталога сборки; проекты на сервере.

**Не-цели.** Изменение вида листа КП, PDF и DOCX сверх названного здесь (новые столбец и строки появляются только
когда менеджер их включил). Отправка КП письмом. Номер КП и журнал отправленных (до этапа 2). Версия для телефона.
Другие сайты. Цены с сайта. Ввод цены в евро.

## 2. Оформление интерфейса

Меняется «обвязка»: форма, список проектов, панель инструментов страницы КП, окно артикулов, страница менеджеров,
сообщения. **Вид листа КП не меняется**: карточка оформления не трогает `src/styles/document.css`, компоненты
листа и DOCX. Разделы 5–7 добавляют на лист новое содержимое (столбец скидки, строка НДС, вторая коллекция,
варианты) в прежнем стиле и только когда менеджер его включил: КП без них выглядит как сегодня. Кнопки на листе
(«×», «вернуть авто», новые «+») — поверх листа, в печать не попадают.

Направление и точные правила — `docs/context/design.md` (метод unslop: тихая обвязка, один акцент, сетка 4 px,
без градиентов, свечения, эмодзи). Раскладка:

```
Форма                                                Страница КП
┌──────────────┬──────────────────────────────────┐  ┌──────────────────────────────────────────────┐
│ Проекты      │ Клиент и менеджер                │  │ К форме │ Отменить Вернуть │ 3 листа │ PDF DOCX│
│ поиск        │ Коллекции (ссылки, режим)        │  │ [Коллекция А][Коллекция Б]  Артикулы  Обновить │
│ список       │ Расчёт: курс, валюта, НДС        │  ├──────────────────────────────────────────────┤
│ (компания,   │ Основные материалы   … Сумма     │  │ Проверьте перед отправкой (предупреждения)   │
│ коллекция,   │ Дополнительные       … Сумма     │  │                                              │
│ дата, сумма) │ Условия и комментарии            │  │            листы A4 — без изменений          │
│ Копия · Новый├──────────────────────────────────┤  │                                              │
│ Импорт, копия│ Общая сумма 395 100,00 ₽ [Создать КП] │                                              │

```

- Форма: слева панель проектов 280 px на всю высоту окна, справа разделы формы; нижняя полоса с общей суммой
  и кнопкой «Создать КП» прилипает к низу окна. Ниже 900 px ширины панель проектов встаёт над формой.
- Таблица материалов — с шапкой столбцов; числа выровнены вправо, табличные цифры.
- Подписи, роли и доступные имена элементов сохраняются (на них стоят тесты); новые тексты — в `design.md`, «Тексты».
- Проверка неизменности листа: до правок стилей снимается эталон — снимки каждого листа КП в Playwright на проекте
  из `e2e/fixtures/project.json`; после правок снимки совпадают попиксельно.

## 3. Форма и проекты

- **Суммы в форме.** В строке материалов — «Сумма» (со скидкой, раздел 5), под таблицей — «Итого», в нижней полосе —
  общая сумма, а при заданном курсе и включённом столбце евро — и сумма в евро. Считает `shared/calc.ts`, тот же
  код, что для КП: числа в форме и в КП совпадают всегда.
- **Копия проекта.** «Создать копию» у текущего проекта: новый `id`, новые `id` строк, всё остальное как есть
  (включая снимок коллекции и правки КП), `kp.date = null`, `kp.fixedDate = null`, к компании ничего не дописывается.
  Копия становится текущей. Картинки общие (хранилище `images` по URL), не дублируются.
- **Список проектов.** Строка: компания (или «Без названия»); под ней коллекция (`collection.name`, при нескольких —
  первая и «+N»), дата `updatedAt` в виде `дд.мм.гг`, общая сумма, фамилия менеджера (первое слово `managerName`).
  Поиск ищет по компании, контактному лицу и названиям коллекций. Порядок — по `updatedAt`, новые сверху.
- **«Сохранено».** Рядом с заголовком формы: «Сохраняем…» пока есть несохранённая правка, затем «Сохранено»;
  при ошибке — нынешнее сообщение об ошибке.
- **Резервная копия (вариант А).** В панели проектов строка «Резервная копия: сегодня / N дн. назад / ещё не
  делалась» и кнопка «Сохранить копию» — то же, что «Экспорт всех проектов» (эта кнопка убирается, «Экспорт проекта»
  и «Импорт из файла» остаются). Время последней копии — `localStorage`, ключ `gelster-kp:lastBackupAt`; ставится
  после скачивания файла со всеми проектами. Строка подсвечивается, если копии нет или ей больше 7 дней и после неё
  менялся хотя бы один проект. При первом сохранении проекта приложение вызывает `navigator.storage.persist()`
  (там, где он есть); отказ браузера ни на что не влияет.

## 4. Строки материалов, окно артикулов, менеджеры

- **Порядок строк.** У строки кнопки «↑» и «↓» (у крайних неактивны); фокус остаётся на перемещённой строке.
- **Вставка из Excel.** Вставка в поле «Наименование» текста с табуляцией или переводом строки раскладывается
  по строкам начиная с текущей. Наименование — первый столбец, который не число и не единица (столбец «№» слева
  пропускается); из чисел правее наименования первое — количество, последнее (если их два и больше) — цена;
  единица узнаётся и в написаниях `шт`, `м2`, `кв.м`, `м.кв`, `п.м`, `пог. м`, `рулон`, `уп`, `компл`, `усл`.
  Числа в виде `1 234,56` и `1234.56`. Ячейка в кавычках с переводом строки внутри (так копирует Excel) — одна
  ячейка, перевод заменяется пробелом. Скидка из вставки не читается. Пустые строки пропускаются; занятые строки ниже не затираются — новые вставляются между ними.
  Обычный текст без табуляции и переводов вставляется как раньше. Разбор — чистая функция с тестами.
- **Окно артикулов.** Поле «Номер артикула» фильтрует сетку по вхождению в `code` и `title`; «Выбрано: N»;
  переключатель «Только выбранные». «Выбрать все» при активном фильтре отмечает только показанные.
- **Правка менеджера.** На странице «Менеджеры» у записи — «Изменить»: имя и (необязательно) новая подпись, те же три
  способа дать файл. Сервер: `POST api/managers.php` с `action=update`, `id`, `name`, необязательным файлом; те же
  пароль и проверка картинки; `id` сохраняется, файл подписи получает новое серверное имя, старый удаляется.
  Клиент: если менеджер проекта есть в списке, подпись берётся по адресу из списка и перезаписывает сохранённую
  в `images`; сохранённая — запас для удалённого менеджера и работы без сети (сейчас сохранённая главнее, и новая
  подпись в старые проекты не попала бы).

## 5. Расчёты и условия предложения

**Единицы.** Порядок в списке: `шт.`, `м²`, `пог.м`, `рул.`, `упак.`, `компл.`, `усл.` (комплект; услуга — укладка,
доставка, подготовка основания).

**Скидка на позицию.** `Item.discountPct: number | null` (0 < x < 100; пусто = нет). Поле «Скидка, %» в строке формы.
- цена со скидкой = `round2(priceRub × (1 − discountPct / 100))`; сумма строки = `round2(qty × цена со скидкой)`;
- столбец «Цена в евро» в КП, как и «Цена», — до скидки: `round2(priceRub / курс)`, как сейчас; сумма в евро
  (видна только в нижней полосе формы) = `round2(qty × round2(цена со скидкой / курс))`;
- в КП (предпросмотр, PDF, DOCX) столбец «Скидка» (`5 %`, у строк без скидки пусто) стоит между ценой и суммой
  и есть только в той таблице, где скидка задана хотя бы у одной строки; «Цена» остаётся ценой до скидки.

**НДС.** `form.showVat: boolean` (по умолчанию `false`), флажок «Показать НДС отдельной строкой». Ставка —
`vatRate` в `config.json` (по умолчанию `22`). В КП под общей суммой (в режиме сравнения — под итогом каждого
варианта) строка «В том числе НДС 22 %:» = `round2(итог × ставка / (100 + ставка))`.

**Условия и комментарии** заменяют переключатель «Комментарий по доставке». `form.terms: Term[]`:

```ts
type Term = { id: string; on: boolean; text: string;
              preset: 'delivery' | 'validity' | 'payment' | 'leadTime' | null;
              date: string | null };   // только у validity: ISO-дата; null = дата КП + 14 дней
```

Новый проект получает четыре фразы, включена только первая:
1. «Доставка до объекта рассчитывается отдельно.» (включена)
2. «Предложение действительно до дд.мм.гггг.» — дата выбирается в поле, текст вокруг даты правится
3. «Условия оплаты: 100 % предоплата.»
4. «Срок поставки: 3–4 недели с момента оплаты.»

Флажок, текст (правится), «+ своя фраза», удаление своей фразы. Свои фразы запоминаются в браузере (хранилище
`idb-keyval`, ключ `phrases`, без повторов, не больше 30) и предлагаются под списком в других проектах. В КП
включённые фразы с непустым текстом идут под таблицами в порядке списка, каждая с тире, как сейчас; за ними —
`kp.comments`. Правка фразы на странице КП пишется в `term.text`; очищенная фраза выключается. Текст срока
действия хранится с меткой `{дата}` («Предложение действительно до {дата}.»), при выводе метка заменяется датой
`дд.мм.гггг`; при правке на странице КП дата в тексте заменяется меткой обратно, а если менеджер дату стёр или
изменил — текст сохраняется как набран, без метки. У предустановленной фразы с изменённым текстом в форме есть
«вернуть стандартный текст». «Создать копию» ставит `date = null`. Свои фразы (`phrases`) входят в файл
резервной копии всех проектов (необязательное поле `phrases` в `ExportFile`) и при импорте добавляются
к имеющимся.

**Версия данных 2.** `form.delivery` → `form.terms`: `default` → четыре фразы, включена первая; `none` → четыре
фразы, все выключены; `custom` → четыре выключенные и по включённой своей фразе на каждую непустую строку.
Появляется `shared/migrate.ts`: `migrateProject(raw) → Project` — цепочка шагов по `version`; через неё читаются
проекты из IndexedDB и из файла импорта (файл версии старше текущей принимается, новее — понятный отказ).
Файл экспорта пишется с текущей версией. `discountPct`, `showVat`, `kp.fixedDate` объявляются с `.default`.

## 6. Страница КП

- **Отменить / Вернуть.** Стек снимков проекта в памяти страницы (до 50 шагов): каждое изменение через `update()`
  (правка текста по `blur`, удаление и добавление блока, артикулы, фото, палитра, «Обновить с сайта») кладёт
  прежний проект в стек. Кнопки в панели и `Ctrl+Z` / `Ctrl+Shift+Z` / `Ctrl+Y`; пока фокус в редактируемом блоке
  или поле ввода, клавиши остаются браузеру (отмена набора текста). Отмена сохраняет проект и перестраивает листы.
  Уход со страницы стек очищает. Правки формы в стек не входят. Нажатие «Отменить» мышью во время правки текста
  сначала сохраняет правку (`blur`), затем отменяет её: текст возвращается к виду до правки (тест).
- **Свои блоки.** При наведении на абзац описания — «+» «Добавить абзац ниже» (пустой абзац сразу в правке; пустой
  после `blur` удаляется); под таблицей характеристик — «+ строка» (ячеек столько же, сколько столбцов; если таблицы нет — две);
  под комментариями — «+ комментарий» (в `kp.comments`). Если описания или характеристик нет, «+» стоит на их месте.
- **Артикулы на листе.** У картинки артикула при наведении «×» (убрать из КП) и «←» «→» (поменять местами
  с соседним по порядку `selectedArticles`).
- **Дата.** `kp.fixedDate: string | null` (ISO). Авто-дата и имя файла = `fixedDate ?? сегодня`. При «Сохранить
  в PDF» и «Сохранить в DOCX», если `fixedDate === null`, она становится сегодняшней. Когда `fixedDate` задана
  и не сегодня — у даты кнопка «сегодня» (ставит сегодняшнюю, сбрасывает ручную правку даты). Срок действия
  (раздел 5) считается от той же даты.
- **Число листов** в панели: «3 листа».

## 7. Несколько коллекций в одном КП

По умолчанию коллекция одна, и всё выглядит как сейчас. Менеджер добавляет вторую и следующие (до 6) и обязан
выбрать режим:
- **«Дополнить коллекции»** — коллекции входят в одно предложение: общие таблицы основных и дополнительных
  материалов и общая сумма, как сейчас.
- **«Сравнить коллекции»** — коллекции-варианты: у каждой свои таблицы основных и дополнительных материалов
  и свой итог; общей суммы нет.

**Данные, версия 3.**

```ts
type Project = { id: string; version: 3; updatedAt: string;
  form: { managerId; managerName; client; clientName; clientSex; euroRate; mainCurrency; extraCurrency;
          mode: 'extend' | 'compare' | null;      // null: коллекция одна или режим ещё не выбран
          mainItems: Item[]; extraItems: Item[];  // общие таблицы: одна коллекция и «дополнить»
          showVat: boolean; terms: Term[] };
  parts: Part[];                                  // не меньше одной; порядок = порядок в КП
  kp: { date; fixedDate; title; greeting; intro; comments } | null };
type Part = { id: string; link: string; collection: Collection | null;
  edits: { collectionHeading; descriptionHtml; selectedArticles; featuresTitle; features;
           mainImageHidden; paletteText; paletteHidden } | null;   // null, пока страница не загружена
  mainItems: Item[]; extraItems: Item[] };        // таблицы варианта: только «сравнить»
```

Шаг миграции 2 → 3: одна часть с `id: 'p1'` из `form.link`, `collection` и полей коллекции из `kp`; `mode: null`.

**Форма.** Раздел «Коллекции»: список ссылок, «+ коллекция», удаление и порядок «↑» «↓». При двух и больше —
обязательный выбор режима (без него «Создать КП» показывает ошибку у переключателя). Одинаковые ссылки — ошибка.
В режиме «сравнить» таблицы материалов показываются по вариантам: «Вариант 1 — Marmoleum Cocoa» (название
из снимка, пока его нет — ссылка), у каждого основные, дополнительные и итог; нижняя полоса показывает итоги
вариантов. Строки всегда лежат в одном месте, скрытых наборов нет: при `mode` «дополнить» и `null` таблицы всех
частей пусты, при «сравнить» пусты общие. Смена режима переносит строки: «дополнить → сравнить» — все общие
строки в первый вариант; «сравнить → дополнить» — строки всех вариантов по порядку в общие таблицы (основные
к основным, дополнительные к дополнительным). Удаление коллекции в режиме «сравнить» спрашивает подтверждение,
если у неё есть строки (они удаляются вместе с ней). Осталась одна коллекция — её строки становятся общими,
`mode = null`. Схема проекта отклоняет запись, нарушающую это правило.

**Документ.** Дата, заголовок, обращение, вступление — один раз. Затем по каждой части подряд: заголовок коллекции,
фото, описание, артикулы, ссылка на палитру, характеристики. Затем расчёт:
- одна коллекция и «дополнить» — как сейчас;
- «сравнить» — «Ниже приведены предварительные расчёты.» один раз; по каждому варианту со строками: строка
  «Вариант N: <заголовок коллекции>» (неделима со следующей таблицей), основные, дополнительные (нумерация строк
  в каждом варианте с 1), «Итого по варианту N в руб., с НДС», при включённом НДС — строка НДС. Общей суммы нет.
Затем условия и комментарии. Принудительного разрыва листа между коллекциями нет.

**Авто-тексты при нескольких коллекциях.** Заголовок: виды покрытий без повторов в родительном падеже через
запятую и «и» перед последним («…на поставку натурального линолеума и грязезащитных покрытий»); производитель
дописывается, только если он один у всех частей. Вступление: те же виды в винительном падеже строчными,
«…а также сопутствующие материалы к ним». Правленые тексты не пересчитываются, как сейчас.

**Страница КП.** В панели — переключатель коллекций (виден при двух и больше; выбор прокручивает к её заголовку);
«Артикулы» (одно окно: отмеченные уже выбраны, снятие убирает, порядок прежних сохраняется, новые в конец —
заменяет «Добавить» и «Перевыбрать»), «Обновить с сайта», «Вернуть фото», «Вернуть ссылку на палитру» действуют
на выбранную коллекцию. При открытии КП грузятся все части без снимка. Окно артикулов само открывается, только
когда коллекция одна (как сейчас); при нескольких КП открывается сразу, а для каждой коллекции без артикулов
в «Проверьте перед отправкой» стоит строка «Не выбраны артикулы: <название>» с кнопкой «Выбрать». Изменённая ссылка части — вопрос о перезагрузке этой части. Часть, которая не
загрузилась, не мешает остальным: предупреждение с её ссылкой. Предупреждения разбора — с названием коллекции.
Идентификаторы блоков и правки (`KpChange`) получают `part`. DOCX и экспорт/импорт следуют модели.

## 8. Этап 2: данные сервера вне сборки и проекты на сервере (не нарезано)

Илья: «вариант Б сделаем потом, вместе с переносом пароля и менеджеров из `dist` в соседнюю папку». Нарезает
отдельная карточка-проектирование (последняя в списке этой задачи); здесь — что уже ясно.

**Б1. Данные и настройки вне каталога приложения.** Сейчас `config.php` и `data/` лежат в `api/` внутри `dist/`:
`npm run build` очищает `dist/`, загрузка на хостинг «с удалением лишнего» стирает их.
- Каталог данных по умолчанию — сосед каталога приложения: `<каталог приложения>/../gelster-cp-data/`
  (в офисе рядом с `dist/`, на хостинге рядом с каталогом сайта, то есть обычно вне веб-корня). В нём `config.php`,
  `managers.json`, `signatures/`, `private/`, позже `projects/`.
- Порядок поиска: переменная окружения → файл-указатель `api/data-dir.php` (возвращает путь; для хостингов, где
  выше каталога сайта писать нельзя) → сосед → прежний `api/data/` (если сосед недоступен; `health.php` говорит,
  где лежат данные и переживут ли они обновление).
- Перенос сам: при первом запросе, если новый каталог пуст, а в `api/` есть `config.php` или `data/`, они
  копируются; старые остаются до ручного удаления.
- Подписи перестают быть статическими файлами: их отдаёт PHP (`managers.php?signature=<id>`), адрес приходит
  в списке менеджеров, клиент не меняется.
- `tools/set-password.php` пишет в новый каталог; README: обновление = заменить каталог приложения целиком.

**Б2. Проекты на сервере.** `config.json`: `storage: "browser" | "server"`. В режиме `server` модуль хранилища
клиента ходит в `api/projects.php` (список-сводка, чтение, запись, удаление; картинки — отдельными файлами по хэшу
содержимого); проект — JSON-файл в `gelster-cp-data/projects/`; запись с номером ревизии, расхождение → 409
и выбор «загрузить новое / записать моё». Локальные проекты переносятся файлом резервной копии (импорт уже есть).
Сервер по-прежнему не знает устройства КП: хранит и отдаёт.

## 9. Риски

| Риск | Что делаем |
|---|---|
| Новое оформление задело лист КП | эталонные снимки листов до правок, попиксельное сравнение после; `document.css` не правится |
| Миграции 1 → 2 → 3 портят проекты | шаги — чистые функции с тестами на сохранённых образцах v1 и v2; до записи мигрированный проект проверяется схемой; совет в README: «Сохранить копию» перед обновлением |
| Файл резервной копии новой версии открыт старой сборкой | импорт отказывает с текстом «файл создан более новой версией приложения» |
| Скидка расходится на копейки с ручным расчётом | правило округления одно (раздел 5), сумма в форме и в КП из одной функции |
| Ставка НДС изменится | `vatRate` в `config.json`; старые КП при открытии покажут новую ставку — отправленные PDF не меняются |
| Несколько коллекций раздувают хранилище и файл копии | не больше 6 коллекций; хранятся только фото и выбранные артикулы, как сейчас; файл копии остаётся JSON с картинками — если он станет слишком большим для браузера, формат меняется на архив (этап 2 снимает вопрос) |
| Заголовок и фото следующей коллекции внизу листа | те же `keepWithNext` у заголовка и фото, что у первой коллекции; сквозной тест с двумя коллекциями проверяет, что заголовок коллекции не последний на листе |
| Таблица с евро и скидкой не помещается по ширине листа | ширины столбцов проверяются снимком листа со всеми столбцами; название позиции переносится по словам |
| Отмена действия после «Обновить с сайта» | снимок проекта содержит прежнюю коллекцию целиком; картинки остаются в `images` |
| Срок действия «дата КП + 14 дней» уезжает, пока КП не сохранено | дата фиксируется при первом PDF/DOCX (раздел 6) |

## 10. Как проверяется

`tests/run.sh` на каждой карточке; новое поведение — с тестом (правило `CLAUDE.md`).
- `shared/calc.ts`: скидка, НДС, итоги вариантов — модульные тесты с числами на границах округления.
- `shared/migrate.ts`: образцы проектов v1 и v2 (в `__fixtures__`) → текущая схема; файл экспорта v1 импортируется.
- Форма: суммы, копия, список, вставка из Excel, условия, режимы коллекций — Testing Library.
- Страница КП: отмена и возврат, добавление блоков, артикулы, дата — `edit.test.ts`, `KpPage.test.tsx`.
- DOCX: столбец скидки, строка НДС, несколько коллекций и варианты — разбор XML, как сейчас.
- PHP: `action=update` — модульно и в `tests/php-api.test.ts`.
- Playwright: эталон листов (раздел 2); полный путь с двумя коллекциями в обоих режимах; печать в PDF — число
  листов равно предпросмотру.
- Руками (Илья): `docs/acceptance.md` дополняется разделом на каждую карточку.
