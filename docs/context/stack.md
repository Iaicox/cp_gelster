# Правила стека (для исполнителей)

Полное решение — `docs/spec.md` (редакция 2: статика + маленький PHP). Здесь только то, что нужно помнить при каждой
правке. Сервера на Node нет и не будет: целевой хостинг не умеет держать процесс Node.

## Общее
- Клиент — статическая сборка (`dist/`), серверная часть — PHP в `api/`. Node нужен только для сборки и тестов.
- Команды: `npm run dev | dev:client | dev:api | build | start | test | test:php | lint | typecheck | e2e`;
  всё сразу — `tests/run.sh`.
- Каталоги: `shared/` (чистый TypeScript), `src/` (клиент), `api/` (PHP), `public/`, `tests/`, `e2e/`,
  `legacy/` (не править).
- Типы данных описываются zod-схемами в `shared/schema.ts`; типы выводятся из схем, не дублируются.
- Новые зависимости — только если без них нельзя; каждая упоминается в `docs/decisions.md` одной строкой.
- Код и коммиты по-английски, тексты интерфейса и ошибок по-русски.
- Секретов в репозитории нет. `api/config.php` и `api/data/` — в `.gitignore` и не попадают в `dist/`.

## Клиент
- React 19, функциональные компоненты, react-router в режиме хэша (`createHashRouter`). Без jQuery, Bootstrap,
  CSS-фреймворков и библиотек состояния.
- Все адреса относительные (`base: './'` в Vite): приложение должно работать из подкаталога и без правил
  перезаписи адресов на веб-сервере. Абсолютных путей вида `/api/...` и `/assets/...` в коде нет.
- В сеть клиент ходит только через `src/api/client.ts`; он читает `config.json` (`apiBase`, `fetchMode`).
  Прямой `fetch` в компонентах запрещён.
- Приложение открывают по `http://` в локальной сети: нельзя полагаться на API, доступные только в защищённом
  контексте (`crypto.randomUUID`, `navigator.clipboard`, service worker). Идентификаторы — через `crypto.getRandomValues`.
- Разбор страниц сайтов — только в `shared/parsers` через `DOMParser`; узлы чужого документа в DOM приложения
  не переносятся. Любой HTML с сайта или из `contenteditable` проходит DOMPurify с белым списком из спеки перед
  вставкой в DOM и перед сохранением. `dangerouslySetInnerHTML` — только с очищенной строкой.
- Стили — обычный CSS: `src/styles/document.css` (страницы КП, размеры в мм/pt, перенос из `legacy/style/style.css`
  без изменения значений) и `form.css`. Размеры КП не «улучшать».
- Проекты и картинки читаются и пишутся только через `src/storage/*`. Расчёты денег — только `shared/calc.ts`.
- Логика разбивки на страницы, построения модели и DOCX — чистые функции, отделённые от React.
- Единицы измерения: `шт.`, `м²`, `пог.м`. Цена вводится только в рублях.

## PHP (`api/`)
- PHP 8.4 и 8.5: код обязан работать на обеих, возможности только 8.5 не использовать. Без фреймворков, без
  Composer, из расширений — только `curl`. `declare(strict_types=1)` в каждом файле.
- PHP ничего не разбирает и не знает о КП: скачать и отдать байты, хранить менеджеров. Логика — в TypeScript.
- Один файл — одна точка входа (`fetch.php`, `rates.php`, `managers.php`, `health.php`), методы только GET и POST,
  без перезаписи адресов. Общий код — в `api/lib/`.
- Наружу по адресу от клиента PHP ходит только через `api/lib/fetch_allowed.php` (белый список хостов, только
  https, редиректы вручную с повторной проверкой, таймауты, лимит размера, проверка IP). `file_get_contents($url)`,
  `CURLOPT_FOLLOWLOCATION` и отключение проверки TLS запрещены.
- Загруженный файл: `is_uploaded_file`, размер, `getimagesize()` (JPEG/PNG по содержимому), имя генерирует сервер.
  Имя и тип, присланные клиентом, не используются.
- Изменение списка менеджеров — только с паролем; хранится хэш (`password_hash`), проверка `password_verify`.
  Пароль и хэш не попадают в ответы, журналы и тесты (в тестах — отдельный тестовый пароль).
- Служебные файлы в `api/data/private/` — `*.php` с первой строкой `<?php http_response_code(404); exit; ?>`:
  `.htaccess` не работает во встроенном сервере PHP и в nginx, полагаться на него нельзя.
- Запись файлов данных — под `flock`, через временный файл и `rename`.
- Ошибки — `{ "error": "..." }` с человеческим текстом по-русски и осмысленным статусом. Заголовков CORS нет.

## Тесты
- Vitest (+ jsdom, `fake-indexeddb`); парсеры тестируются на сохранённых страницах в `shared/parsers/__fixtures__/`.
- PHP: `tests/php/run.php` (модульные, без зависимостей, сеть подменяется транспортом) и `tests/php-api.test.ts`
  (Vitest поднимает `php -S`). Нет `php` в системе — эти тесты пропускаются с заметным предупреждением;
  `REQUIRE_PHP=1 tests/run.sh` делает пропуск ошибкой. Остальные тесты от PHP не зависят.
- Сквозные тесты Playwright подменяют сеть фикстурами и PHP не требуют. Живая сеть в `tests/run.sh` не используется.
- Тесты не ослаблять ради зелёного прогона. Изменилась вёрстка сайта — обновить фикстуру отдельным коммитом.
