# Генератор КП Гельстер

Генератор коммерческих предложений по коллекциям с сайтов gelster.ru и ooogelingen.ru: форма запроса, страница КП,
выгрузка в PDF (печать браузера) и DOCX. Идёт переписывание старой PHP-версии (лежит в `legacy/` до приёмки новой).

Устройство: клиент — статическая сборка React (`dist/`), серверная часть — несколько PHP-файлов в `api/`
(загрузка страниц и картинок с двух сайтов, курс ЦБ, список менеджеров). Node.js нужен только для сборки и тестов.
Спецификация — `docs/spec.md`, решения — `docs/decisions.md`, правила стека — `docs/context/stack.md`.

## Требования к хостингу

- PHP 8.5 (патч не ниже 8.5.12); допустим PHP 8.4. Ниже 8.4 API отвечает ошибкой «Нужен PHP 8.4 или новее».
- Расширение PHP `curl` (остальное — из ядра PHP). Composer и фреймворки не нужны.
- Разрешены исходящие https-запросы из PHP (к gelster.ru, ooogelingen.ru, cbr.ru).
- У PHP есть право записи в каталог `api/data/` (или в `api/`, чтобы он создал `data/` сам).
- На публичном хостинге — только https: пароль администратора передаётся в каждом изменяющем запросе.
- Веб-сервер любой (Apache, nginx, встроенный сервер PHP): правила перезаписи адресов не нужны, приложение
  работает и из подкаталога сайта.

## Разработка

Нужны Node.js (`^22.22.2 || ^24.15.0 || >=26`) и npm; для API — PHP. На `srv` (Debian 13, PHP 8.4):

```sh
sudo apt install php-cli php-curl
```

```sh
npm ci
npm run dev          # Vite на http://127.0.0.1:5173 + php -S 127.0.0.1:8081 -t . ; Vite проксирует /api на PHP
npm run dev:client   # только интерфейс, без PHP: сетевые функции будут показывать ошибку
npm run dev:api      # только PHP на 127.0.0.1:8081 (порт для прокси Vite меняется переменной PHP_PORT)
```

## Проверки

```sh
tests/run.sh               # всё сразу: typecheck, lint, Vitest, php -l по api/, PHP-тесты
REQUIRE_PHP=1 tests/run.sh # то же, но отсутствие php — ошибка, а не пропуск
npm run typecheck
npm run lint
npm test                   # Vitest; тесты эндпоинтов поднимают php -S сами и пропускаются, если php нет
npm run test:php           # модульные тесты PHP (tests/php/run.php)
tests/smoke-live.sh        # живая проверка (нужна сеть): страница и картинка с обоих сайтов, курс ЦБ через php -S
npm run e2e                # сквозные тесты Playwright (страница КП, разбивка, печать в PDF); сеть подменена фикстурами
```

`npm run e2e` сам поднимает Vite на порту 5199 (`E2E_PORT`), PHP не нужен. Браузер — Chromium, скачанный
Playwright (`npx playwright install chromium`); если его нет, берётся `PLAYWRIGHT_CHROMIUM_EXECUTABLE`, более
старая загрузка из `~/.cache/ms-playwright` или системный `/usr/bin/chromium`. В `tests/run.sh` не входит.

Если `php` не установлен, `tests/run.sh` печатает «PHP НЕ НАЙДЕН: тесты PHP ПРОПУЩЕНЫ» и завершается успешно.

## Сборка

```sh
npm ci
npm run build
```

Результат — каталог `dist/`: `index.html`, `config.json`, ассеты и `dist/api/` (копия `api/` без `config.php`
и `data/`). Все адреса в сборке относительные, маршруты в хэше (`#/`, `#/kp/<id>`, `#/managers`).

## Запуск в офисе

```sh
npm start                    # php -S 127.0.0.1:8080 -t dist
HOST=0.0.0.0 npm start       # открыть в локальной сети; порт меняется переменной PORT
```

Проверка: `curl -s http://127.0.0.1:8080/api/health.php` →
`{"ok":true,"phpOk":true,"curl":true,"dataWritable":true,"passwordSet":false}`.
Вместо встроенного сервера можно отдать `dist/` через Apache или nginx с PHP — настройка адресов не нужна.

## Установка на хостинг

1. Собрать (`npm run build`) и загрузить **содержимое** `dist/` в каталог сайта (корень или любой подкаталог).
2. Открыть в браузере `<адрес приложения>/api/health.php`: `ok: true` — PHP, `curl` и запись в `api/data/` в порядке.
   `phpOk: false` — старый PHP; `curl: false` — нет расширения; `dataWritable: false` — дать PHP право записи
   в `api/` или `api/data/`; `passwordSet: false` — пароль ещё не задан (см. ниже).
3. Открыть `<адрес приложения>/`.

`config.json` рядом с `index.html` меняется без пересборки: `apiBase` — каталог API (`"api"`, или `null` — работа
без сервера), `fetchMode` — `"proxy"` (страницы через `api/fetch.php`) или `"direct"` (браузер ходит на сайты сам,
нужны заголовки CORS на сайтах). Подробнее — `docs/spec.md`, раздел 4.

## Обновление

Загрузить новую сборку поверх старой, **не затирая**:
- `api/config.php` — пароль и настройки;
- `api/data/` — список менеджеров, подписи, служебные файлы;
- `config.json` — если правили его на хостинге.

`npm run build` сам не кладёт `config.php` и `data/` в `dist/`, но при загрузке «с удалением лишнего» (sync/mirror)
эти файлы на хостинге надо исключить.

## Пароль администратора

Изменение списка менеджеров требует пароля; пока он не задан, изменения отклоняются, список читается.
В `api/config.php` хранится только хэш. Образец — `api/config.example.php`.

Пароль задаётся командой (спросит пароль дважды, не короче 8 символов; запишет хэш в `api/config.php`, остальные
ключи сохранит):

```sh
php api/tools/set-password.php
```

Через веб `api/tools/*.php` отвечают 404. После 5 неверных попыток за 15 минут вход с этого адреса блокируется
на 15 минут (ответ 429); каждая неверная попытка отвечает с задержкой 1 с.

На хостинге без командной строки `config.php` готовится на своём компьютере и загружается в `api/` на хостинге.

## Печать

PDF — кнопка «Сохранить в PDF» на странице КП: открывается печать браузера, в ней «Сохранить как PDF». Поля
страницы задаёт само приложение (`@page { size: A4; margin: 0 }`); при нулевых полях Chrome и Edge не печатают
дату, адрес и номера страниц, флажок «Колонтитулы» снимать не нужно. Имя файла подставляется само:
`КП_<компания>_от_дд.мм.гг`. Масштаб в диалоге — 100 %.

Если появились поля: Печать → Поля → По умолчанию (Chrome запоминает последний выбор; при «Обычные» или
«Настраиваемые» колонтитулы возвращаются). Поддерживаются Chrome и Edge.
